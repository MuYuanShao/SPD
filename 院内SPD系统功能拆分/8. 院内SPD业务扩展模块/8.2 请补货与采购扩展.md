# 8.2 请补货与采购扩展

> 所属模块：8. 院内SPD业务扩展模块
> 来源：院内SPD系统产品需求文档.md

## 当前实现基线（2026-07-13）

**实现状态：部分实现。** 已有安全库存、周期消耗补货公式、智能补货分析、采购需求、计划和订单主流程。

- 补货数量保留周期天数、周期出库量、日均出库量、公式建议量、人工调整标记和公式说明。
- 采购计划与来源需求通过 `purchase_plan_demand` 记录明确分配关系，避免隐藏来源。
- 采购订单支持分页、明细、状态动作和补货分析输入。
- 单据号通过数据库序列统一生成，属于并发验证重点。
- [ ] 预测模型效果、参数治理、供应商交期反馈和自动下单策略仍需真实业务数据验收。

## 8.2.1 功能概述

补充 SPD 院内"请补货 → 申购 → 采购套餐 → 中心库/科室分级审批 → 请货单"的完整业务链，覆盖审计中缺失的自动请补货、定数包/一物一码安全量监控、采购套餐、申购、请货单等节点。

## 8.2.2 功能架构

```
请补货与采购扩展
├── 自动请补货管理
│   ├── 补货策略配置

│   └── 请补货单生成
├── 安全量配置与监控
│   ├── 定数包模板维护
│   ├── 定数包安全量维护
│   ├── 定数包材料对应安全量监控
│   └── 一物一码材料对应安全量监控
├── 申购管理
│   ├── 申购单新建
│   ├── 申购审批
│   └── 申购转采购
├── 采购套餐维护
├── 中心库采购审批

```

## 8.2.3 自动请补货管理

**补货策略配置：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 策略名称 | 是 | 中心库定时补、科室二级库实时补、定数包阈值补 |
| 触发条件 | 是 | 库存 ≤ 安全库存 / 定数包消耗率 ≥ 阈值 / 一物一码缺货 |
| 扫描频率 | 是 | 实时 / 5 分钟 / 30 分钟 / 每日 |
| 适用库房 | 是 | 多选 |
| 适用产品分类 | 否 | 不选则全部适用 |
| 自动提交 | 是 | 是：直达审批；否：草稿待人工确认 |

**请补货单生成流程：**

```
[定时任务/事件触发] → [扫描安全量] → [按补货策略计算补货量]
    → [生成请补货单（草稿）] → [按策略自动/手动提交]
    → [中心库或上级库房审批] → [转采购订单 或 转调拨单]
```

| 字段 | 说明 |
|------|------|
| 请补货单号 | BHD + YYYYMMDD + 4位序号 |
| 申请库房 | 自动带入 |
| 目标库房 | 上级库房 |
| 触发策略 | 自动带入 |
| 明细 | 商品、当前库存、安全库存、建议补货量、实际补货量 |

## 8.2.4 定数包模板维护

定数包模板用于维护包族、模板版本、包内商品及包装数量，是后续安全量配置、打包、消耗、反消耗和红冲追溯的基础。模板发布后生成版本号，历史模板不得覆盖修改；新版本只影响后续新打包。

| 字段 | 必填 | 说明 |
|------|------|------|
| 包族编码 | 是 | 唯一，表示同一业务含义的定数包，如骨科手术包 |
| 定数包名称 | 是 | 例：骨科手术包 |
| 模板版本 | 自动 | 发布时生成，禁止覆盖旧版本 |
| 包内商品 | 是 | 商品 + 包装数量 + 单位；仅允许选择 `是否定数管理 = 是` 的商品 |
| 状态 | 是 | 草稿 / 已发布 / 已停用 |
| 适用说明 | 否 | 使用场景、打包注意事项等 |

**模板发布规则：**

- 发布时校验包内商品主数据 `是否定数管理 = 是`。
- 高值耗材和冷链试剂不纳入定数包模板。
- 已发布模板不得直接覆盖修改，变更包内商品或包装数量时发布新版本。
- 打包生成定数标签时固化当时模板版本和包内明细快照。
- 新版本发布后默认自然替换，旧版包允许继续消耗。

## 8.2.5 定数包安全量维护

定数包安全量维护用于配置院区、科室、库房维度的定数包保有量和补货策略。安全量按包族配置，可用库存默认跨模板版本汇总，新增补货按当前启用版本打包。

| 字段 | 必填 | 说明 |
|------|------|------|
| 院区 | 是 | 多院区场景必填 |
| 科室 | 是 | 定数包使用科室 |
| 库房/货位 | 否 | 科室二级库或指定货位 |
| 包族编码 | 是 | 引用定数包模板维护中的包族编码 |
| 安全包数 | 是 | 该科室必须保有的最低包数 |
| 最大包数 | 否 | 上限，超量不再补 |
| 补货策略 | 是 | 阈值补 / 定时补 / 手动补 |
| 状态 | 是 | 启用 / 停用 |

## 8.2.8 申购管理

申购（科室/部门发起的非急用物资申请，区别于"申领"——申领针对已在目录的常用物资，申购可申请尚未入院或非常规物资）。

| 字段 | 必填 | 说明 |
|------|------|------|
| 申购单号 | 自动 | SG + YYYYMMDD + 序号 |
| 申购科室 | 是 | 自动带入 |
| 申购类型 | 是 | 新品申购 / 临时申购 / 试用申购 |
| 商品（库内/外购） | 是 | 库内可选商品；外购填写名称、规格、厂家、参考价 |
| 数量、用途 | 是 | - |
| 期望到货时间 | 是 | - |
| 附件 | 否 | 临床论证、价格对比 |

**申购流程：**
```
[科室发起] → [科室主任审批] → [医务/设备科论证] → [运营管理员审批]
    → [转商品准入流程或直接转采购] → [完成]
```

## 8.2.10 中心库采购审批

中心库（SPD 中心仓）发起的采购订单审批节点，与原 5.1.6 金额分级审核规则结合：

| 条件 | 中心库审批人 | 时限 |
|------|--------------|------|
| 套餐采购、合同价 | 采购主管 | 即时 |
| 非合同价、金额 ≤ 5 万 | 采购主管 + 运营管理员 | 1 工作日 |
| 5 万 < 金额 ≤ 50 万 | 采购主管 + 财务 + 运营管理员 | 2 工作日 |
| 金额 > 50 万 | 采购主管 + 财务 + 院领导 | 3 工作日 |
| 紧急采购 | 中心库主任先批，事后补流程 | 24 小时内 |

## 8.2.11 科室采购审批

科室直接发起的采购（非中心库统一采购，例如科室专项设备耗材）需独立审批节点。

| 条件 | 科室审批人 | 后置环节 |
|------|------------|----------|
| 金额 ≤ 5000 | 科室主任 | 中心库登记备案 |
| 5000 < 金额 ≤ 5 万 | 科室主任 + 运营管理员 | 中心库代采 |
| 金额 > 5 万 | 科室主任 + 院领导 | 进入中心库采购流程 |

## 8.2.12 请货单管理

请货单（科室/二级库 → 中心库的物资请领单据，是 SPD 院内最常见的"请货"业务对象，区别于面向供应商的采购订单）。

**请货单字段：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 请货单号 | 自动 | QH + YYYYMMDD + 序号 |
| 请货库房 | 是 | 申请方（通常是科室二级库） |
| 目标库房 | 是 | 中心库 |
| 请货类型 | 是 | 常规 / 紧急 / 定数包补给 / 散货补给 |
| 请货明细 | 是 | 商品、申请量、单位、备注 |
| 期望到货 | 是 | - |
| 备注 | 否 | - |

**请货单审核：** 由中心库审核员根据库存、效期、批号情况确认是否满足，可整单/分行通过/驳回。

**请货单查询：** 支持按"申请库房 / 状态 / 日期范围 / 商品 / 申请人"多维筛选；支持导出 Excel；支持反查关联出库单/补货单/到货回单。

**科室申领单配送审核：** 中心库出库前对申领单 / 请货单进行配送复核（拣货完成后第二道把关）：
- 数量复核、批号一致性、效期校验、定数包完整性。
- 复核通过 → 进入「出库配送」节点；不通过 → 退回拣配重新作业。

## 8.2.13 补货定时任务、缺货登记与来货匹配

补货任务由定时任务统一扫描生成，支持按配置生成“补货建议”或“正式补货任务”。紧急补货可由人工即时创建，不必等待定时任务。补货任务生成后不锁定具体库存，拣配扫描定数包标签或散货明细时才锁定库存。

**定时任务配置：**

| 配置项 | 说明 |
|--------|------|
| 执行频率 | 支持按医院、院区、库房、科室、商品分层配置 |
| 执行模式 | 生成建议 / 直接生成正式任务 |
| 扫描范围 | 科室、库房、商品分类、商品、定数包包族 |
| 生成策略 | 补到最小 / 补到目标 / 补到最大，支持配置 |
| 合并规则 | 默认合并同科室同商品或同定数包的未执行任务；已锁定、已拣配、已出库、在途任务不合并 |
| 时间窗 | 支持每日固定时间窗、工作日/节假日策略、手动触发 |
| 失败处理 | 失败重试、任务日志、执行状态和告警 |

**触发来源：**

- 安全量不足。
- 召回、隔离、盘亏、报损导致可用库存下降。
- 反消耗恢复导致补货任务需重算。
- 科室紧急补货申请。
- 缺货登记来货匹配。

**紧急补货规则：**

- 紧急补货优先占用未锁定库存，但不抢占普通补货中已锁定未出库的库存。
- 紧急补货禁止负库存；库存不足时转调拨、紧急采购或应急借用流程。
- 应急借用必须绑定真实实物来源，不能作为系统凭空生成库存的入口。

**库存不足与缺货登记：**

| 场景 | 处理规则 |
|------|----------|
| 库存足够 | 按建议数量生成补货建议或任务 |
| 库存不足 | 支持部分满足，并记录未满足缺口 |
| 未满足缺口 | 自动生成缺货登记，来货后优先处理缺货登记对应科室/单据 |
| 禁止事项 | 不允许通过负库存表达缺货，不允许生成超出可用库存的出库任务 |

缺货登记必须明确缺货类型，至少包括定数包、散货、高值、冷链。定数包缺货按包数满足，散货按明细数量满足，高值/冷链按 UID/唯一码或明细数量满足。缺货登记排序按紧急等级和登记时间处理，支持可配置权重并允许库管人工调整且留痕。缺货满足以科室签收或确认收到为准，中心库出库在途不视为满足；缺口完全满足后自动关闭，未满足时允许人工带原因关闭。

**来货匹配规则：**

- 收货上架完成后，系统支持自动匹配缺货登记，并按配置生成补货建议或正式补货任务。
- 定数管理商品来货后，优先按配置生成打包建议或打包任务，再用已生成的定数包满足缺货登记。
- 定数包缺货默认通过打包后补包满足；是否允许散货替代定数包缺货由前台配置控制。若配置允许，散货替代可满足临床缺货登记，但是否关闭定数安全量缺口按配置执行。
- 缺货登记关闭只看缺货数量是否被满足，不取决于来源是正常补货、调拨、紧急采购还是应急借用。
