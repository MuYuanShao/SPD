# 8.3 收货与上架管理

> 所属模块：8. 院内SPD业务扩展模块
> 来源：院内SPD系统产品需求文档.md

## 8.3.1 功能概述

补充 SPD 院内"B2B 配送 → 多模式收货 → 收货打包 → 客户端标签上架 → 上架/收货查询"完整链条，覆盖低值/高值/散货/期初等场景。

## 8.3.2 功能架构

```
收货与上架管理
├── B2B 配送单确认
├── 多模式收货
│   ├── 根据请货单的手工收货
│   ├── 散货收货
│   ├── 高值手工收货
│   └── 期初入库
├── 收货打包
├── 客户端标签上架
├── 打包及上架查询
└── 收货查询
    ├── 收货查询（新节点-总览）
    ├── 低值收货查询
    └── 高值收货查询
```

## 8.3.3 B2B 配送单确认

供应商通过 B2B 平台推送配送单到 SPD，库管员确认是否到货：

| 字段 | 说明 |
|------|------|
| B2B 配送单号 | 来自外部 B2B 平台 |
| 关联采购订单 | 双向关联 |
| 供应商 | - |
| 预计到货时间 | - |
| 配送明细 | 商品、批号、效期、数量、单价 |
| 配送状态 | 已发车 / 已送达 / 已确认 / 拒收 |

**操作：**
- **整单确认**：扫描配送单号，全部确认收到 → 自动生成收货单。
- **逐项确认**：按行逐项核对（数量/批号/效期），允许差异处理。
- **拒收**：填写拒收原因，回写 B2B 平台。

**B2B 配送单都在此确认**——所有 B2B 推送的配送单统一在此节点确认，避免散落到各业务模块。

## 8.3.4 根据请货单的手工收货

科室二级库收到中心库配送的物资后，按请货单逐项手工收货：

| 字段 | 说明 |
|------|------|
| 请货单号 | 扫码或选择 |
| 配送单号 | 自动带入（来自中心库出库） |
| 收货明细 | 商品、应收量、实收量、批号、效期、差异原因 |
| 差异处理 | 短少 / 破损 / 多送 → 反馈中心库 |

**收货流程：**
```
[扫描请货单/配送单] → [核对明细] → [扫描产品码（UDI/RFID）] → [录入实收量]
    → [差异行标注] → [整单提交] → [更新二级库库存] → [生成科室收货回单]
```

## 8.3.5 散货收货

中心库或二级库对散货（已拆包/拆零的零散物资）的专项收货：

| 场景 | 处理 |
|------|------|
| 整件拆零后剩余散货 | 扫码识别散货标签 → 上架到散货引导货位 |
| 退回散货（科室退库） | 进入隔离区域，待审核 |
| 供应商按散货发货 | 直接收货并按引导货位上架 |

**散货标识：** 系统打印散货标签，含「商品编码、批号、剩余件数、引导货位」。

## 8.3.6 高值手工收货

高值耗材必须按件扫码收货（一物一码），不允许批量录入：

| 必录字段 | 说明 |
|----------|------|
| UDI 码 | 必扫，关联 6.1 UDI 追溯 |
| 序列号 | 来自 UDI 解析 |
| 批号 | 来自 UDI 解析或人工录入 |
| 注册证号 | 自动校验 |
| 效期 | 自动校验，过期不允许入库 |
| 货位 | 高值位 |
| 收货人 | 自动带入 |

**与一般手工收货差异：** 强制单件扫码、强制货位、强制注册证有效性校验。

## 8.3.7 期初入库

系统上线/年度盘整时使用，导入历史库存或盘点结果到指定库房：

| 字段 | 说明 |
|------|------|
| 期初单号 | QC + YYYYMMDD + 序号 |
| 期初类型 | 上线初始化 / 盘整调整 |
| 库房 | 是 |
| 明细 | 商品、批号、效期、数量、单价、货位 |
| 来源说明 | 必填，留痕 |

**控制规则：**
- 仅运营管理员有权操作；不进入采购/财务结算流程；只更新库存。
- 操作完成后自动锁定，禁止二次修改（如需调整须走盘点单）。
- 正式上线前必须完成数据初始化/迁移验收，验收未完成不得切换生产使用。
- 初始化范围至少包括商品目录、供应商、科室、库房、货位、角色权限、配置默认值、期初库存、定数模板/系数/安全量、高值耗材和冷链试剂 UID/唯一码。
- 期初库存必须按系统批次、生产批号、效期、批次单价、所有权、结算模式、库房/货位建立账面库存；不允许用负库存、虚拟入库或无实物来源数据兜底。
- 商品启用定数管理后，历史散货库存不自动转换为定数包；如需成包，必须由授权人员发起历史散货初始化打包，并遵守完整成包条件。
- 初始化差异必须通过盘盈盘亏、库存调整或业务审批流程处理，并保留差异原因、处理人、审批人、处理时间和附件。
- 期初库存和关键主数据必须由对应库房、科室、运营或财务责任人签字确认，形成上线验收附件。

## 8.3.8 收货打包

到货验收后将散件按发科室/规则打包，便于后续配送：

| 操作 | 说明 |
|------|------|
| 按定数包打包 | 按定数包配方自动归集，打印定数包标签 |
| 按科室打包 | 按申领/请货目的科室打包 |
| 按手术单打包 | 关联手术单的耗材打成手术包 |
| 自由打包 | 临时手动打包 |

**打包标签字段：** 包号、目的库房/科室、商品清单、打包人、打包时间、二维码（含包号）。

## 8.3.9 客户端标签上架

收货 / 打包完成后通过 PDA（手持客户端）扫码上架：

| 流程 | 说明 |
|------|------|
| 1. 扫描标签 | PDA 扫描产品码 / 包号 |
| 2. 推荐货位 | 系统按引导货位 / 容量算法推荐 |
| 3. 扫描货位 | PDA 扫描货位码确认 |
| 4. 提交上架 | 库存绑定货位，记录操作日志 |

**异常处理：** 货位类型不匹配（如冷链商品上架到普通货位）→ 报错阻断。

## 8.3.10 打包及上架查询

| 维度 | 说明 |
|------|------|
| 按打包单查询 | 包号、打包时间、打包人、打包内容、状态（已上架/未上架） |
| 按上架记录查询 | 货位、商品、上架人、上架时间 |
| 按异常查询 | 上架失败、滞留未上架（超过 X 小时未上架报警） |

## 8.3.11 收货查询新节点

统一收货查询入口，整合各类收货数据（采购收货 / B2B 收货 / 请货单收货 / 散货 / 高值 / 期初）：

| 查询条件 | 说明 |
|----------|------|
| 收货类型 | 多选 |
| 来源单据 | 采购单 / B2B 配送单 / 请货单 / 期初单 |
| 商品 / 供应商 / 批号 | 多维筛选 |
| 收货时间范围 | 必填 |
| 异常标记 | 是否有差异 |

## 8.3.12 低值收货查询

|------|------|

| 商品 / 批号 / 效期 | - |
| 数量、单价、金额 | - |

聚焦高值耗材，重点关注「单件溯源」：

| 字段 | 说明 |
|------|------|
| UDI 码 | 唯一标识 |
| 序列号 | - |
| 注册证号 / 注册证有效期 | - |
