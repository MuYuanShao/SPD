## 修复结果

| 编号 | 修复 | 验证 |
|---|---|---|
| F1 | 按申请、来源商品和稳定 sourceLicenseId 查找并替换旧待审批附件，清除旧可变编号映射 | 单元用例先失败后通过；真实双端审批前改号只保留两份当前证照，审批后不提升旧附件 |
| F2 | MCP 计划转单先锁计划行，再检查状态并建立剩余量读取快照 | 用 ID 序列行锁形成并发屏障，两次真实 HTTP 请求仅一次成功；只落一张20元订单、10件配送；保留并发编辑拒绝测试 |
| F3 | active 下发对停用商品保存明确启用审批目标；审批前不直接改商品状态 | 双端验证停用→待审批 targetStatus=1→批准后启用；独立证照重发不抹掉在途启用目标，纯资质审批不意外启用 |
| F4 | 十份额度只计算未撤销证照，撤销元数据完整保留，总元数据条数上限1000 | 同一稳定 productId 下新建并软删除11份证照，商品仍能下发；SPD精确收到这11个来源ID的 revoked 意图 |

## 兼容与交付范围

双端需一起更新证照额度规则；旧SPD接收器仍会拒绝超过十条的完整集合。默认完整HTTP期限仍为15秒，双方可分别配置 `SPD_MCP_HTTP_TIMEOUT_MS`、`SPD_PR_HTTP_TIMEOUT_MS`；响应字节上限仍为1MB及64KB。

本轮没有新增业务库迁移、修改既有迁移或启用新的同步类型，也未回写现有业务库的历史附件。两仓库原有用户截图及无关文件保持。
