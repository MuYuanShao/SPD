# SPD × MCP 业务操作思维导图

生成日期：2026-11-02。依据当前业务口径及2026-10-31混合计划修复验收整理。本文件为操作大纲，不包含账号密码或真实患者信息。

阅读方式：节点中的SPD/MCP/科室/财务标明责任方，箭头标明跨端方向。核心闭环已验证；扩展运营菜单及外部HIS、付款需按实际环境另行验收。

## 01 账号与对接准备

### [管理员] 分配操作职责

- SPD：采购、库房、科室、财务按权限操作
- MCP：供应商仅访问自身已授权业务

### [SPD → MCP] 合作方主数据

- 维护院内供应商、厂家并上传MCP
- 确认合作方对应关系后下发商品

### [管理员] 配置医院实例

- 确认机构、接口地址、认证及同步开关
- 供应商账号绑定院内配送商范围

### [两端] 访问与授权

- SPD局域网入口：172.16.2.153:1820
- 登录使用现有账号；页面及API均校验权限

## 02 商品目录与证照

### [MCP] 维护商品及证照

- 填写商品、规格、单位、价格、厂家、配送商
- 维护注册证、经营/生产资质及有效期、附件
- 续证、更新或停用时保留历史记录

### [MCP → SPD] 下发与受理

- 下发商品目录、证照及附件
- SPD形成待审批资料；下发成功不等于准入通过
- SPD查看证照台账及附件，支持的格式可预览

### [SPD] 审批生成医院目录

- 院方完成准入审批，确认管理属性
- 低值定数、高值唯一码由院内明确设置

### [SPD] 建立科室目录

- 绑定商品与科室库房；配置可申领范围
- 低值定数商品维护包模板及每包基础数量

## 03 混合计划与自动拆单

### [SPD] 采购需求与混合计划

- 手工需求或补货分析 → 需求审核 → 生成计划
- 一张计划可混合高低值及多个配送商

### [SPD] 审前确认明细

- 逐条确认商品、数量、单位及配送商
- 保存计划估价快照；审批开始后不得静默改动

### [SPD] 最终审批自动拆单

- 多级审批全部通过才生成采购订单
- 按明细配送商分组；同配送商高低值合为一单

### [SPD → MCP] 上传供应商订单

- 订单共同关联原计划；新订单承接审批授权
- MCP各供应商仅见自己的订单及计划明细

## 04 供应商供货与院方收货

### [MCP] 按医院订单供货

- 选择可供货明细，填写数量、批号及日期
- 选择院内收货库房；按需填写UDI及备注

### [MCP → SPD] 供货回传

- 提交后持久发送，SPD生成独立待收货草稿
- 回传成功不自动验收、不增加库存

### [SPD] 实物收货与质检

- 核对实收、合格、不合格数量及批次信息
- 审核后仅合格数量入一级库；拒收不入库
- 系统批次单价按验收时医院目录采购价形成

### [SPD → MCP] 验收回执

- 供应商刷新查看草稿、已验收或拒收状态
- 回执展示实际验收数量；保留原供货申报

## 05 一级库与定数包

### [SPD] 批次与库存查询

- 按库房、商品、批次查询库存余额
- 库存交易流水单独查询，不混入余额页

### [SPD] 低值定数包作业

- 模板定义每包数量 → 创建打包任务并预留
- 确认打包 → 生成标签 → 打印后供拣配

### [SPD] 高值唯一码库存

- 合格收货按件形成稳定唯一码身份
- 按批次、有效期及当前库房追溯每件耗材

### [SPD] 数量与包装口径

- 散货转包后分别核对散货和包内实物数量
- 按基础单位折算，防止把同一实物重复计数

## 06 科室申领、拣配与签收

### [科室 / SPD] 发起申领

- 先看历史申领单；新增仅查询当前科室目录
- 支持定数包、高值唯一码和散货混合申请

### [一级库 / SPD] 审批与拣配

- 审批后按申领明细选择包码、唯一码或批次
- 扫码绑定配送单；已占用货源不得重复拣配

### [一级库 → 二级库] 配送在途

- 高值扫码占用即预扣；在途不等于科室入库
- 签收前不正式扣减一级库、不增加二级库

### [科室 / SPD] 签收转库

- 签收后一级库正式扣减、科室库同步增加
- 重复签收不重复转移库存；签收不代表计费

## 07 科室消耗与高值计费

### [科室 / SPD] 低值消耗

- 定数包按包码扫描消耗，关联原批次和包量
- 散货按有效业务数量消耗并扣减科室库存

### [HIS / 手麻 → SPD] 高值计费

- 接收患者、耗材唯一码及外部计费单号
- 真实计费回传后扣减对应科室库存

### [SPD] 追溯与收费查询

- 保留商品、批次、唯一码及业务单据关系
- 收费明细支持患者、住院号、耗材等检索

### [SPD] 防止重复及越权

- 重复计费回传不重复扣库；重复包消耗拒绝
- 科室取出、拣配、签收均不能替代计费事实

## 08 结算数据与供应商协同

### [SPD] 到达结算点生成单据

- 普通非定数低值：采购入库；定数包：科室消耗
- 高值：实际计费；按批次结算点及来源生成

### [SPD → MCP] 上传结算头及明细

- 保留来源数量、单价、四位金额、币种与税口径
- 不同供应商仅接收各自的结算及来源明细

### [MCP → SPD] 对账协同反馈

- 供应商查看、核对结算，提交确认或异议反馈
- 反馈仅用于协同，不直接修改库存或院内金额

### [SPD / 财务] 院内确认与后续

- 院内结算确认由SPD授权流程控制
- 接收到结算、反馈确认均不等于已付款

## 09 异常处理与业务边界

### [两端] 失败重试与重复防护

- 网络失败保留原消息重试；校验失败修正后重提
- 重复操作不重复建单、入库、转库或扣库

### [SPD] 退回、拒收及受控纠正

- 准入退回补资料；供货异常按收货状态处理
- 消耗红冲受结算状态及权限约束，不强行改账

### [SPD] 扩展运营业务

- 盘点、调价、召回隔离、冷链、退货及PDA
- 按独立功能操作；不默认全部自动与MCP闭环

### [管理端] 运行核对与留痕

- 核对待处理消息、失败原因及供应商授权
- 单据、批次、追溯及审计保持可查；付款另核实

## 贯穿样例

测试A供应商配送低值MCPg 20支，测试B供应商配送高值MCPd 4支：同一混合计划最终审批后生成两张订单。收货后科室申领低值2包（每包5支）及高值2支，扫码拣配形成占用，签收后一级库剩低值10支/高值2支，科室库存为低值10支/高值2支。低值消耗一包、高值模拟HIS计费一支后，科室剩低值5支/高值1支，分别生成12.5000元和100.0000元结算。

该数量示例来自独立环境复测；不能理解为导出导图时再次操作了业务库存。
