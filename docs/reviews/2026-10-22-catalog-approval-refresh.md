# 审批同标签与关联刷新验证记录

日期：2026-10-22。

## 范围与需求

按用户确认的建议实施：审批列表与详情复用一个业务标签；返回保留筛选、页码和滚动位置；审批成功刷新相关列表及待办，最终审批通过后刷新医院目录。保留原有后端事务与审批节点语义。

比较基线为本次修改前保存的 `output/approval-refresh-baseline/manifest.json` 及对应文件，排除工作区此前已存在的菜单、日志和中文文案改动。

## 实现

- 路由元信息提供稳定的模块标签标识，标签保留实际详情地址；导航成功后再移除标签。
- Pinia 仅保存失效版本号；审批列表、医院目录和工作台按激活状态刷新真实 API。没有新增模拟业务数据或后端接口。
- 缓存列表保留查询上下文，刷新后校正空的末页；请求序号丢弃已过期响应。
- 详情切换审批单时清空意见与反馈；提交期间锁定输入、离开和重复请求，保留未保存修改确认。
- 批量接口仅返回数量，存在成功项时保守刷新医院目录；单笔只有最终 approved 才使医院目录失效。列表显示批量成功与失败数量。

## Standards

独立 Agent 审计并复核。发现并修复两项 P2：缓存切单时意见残留、延迟的列表激活回调滚动其他页面。最终未发现剩余可操作问题。

## Spec

另一独立 Agent 审计并复核。发现并修复三项：取消离开时活动标签被提前删除、提交期间编辑造成保存竞态、批量提交时可提前离开并读取过期详情。结果提示的后续修复亦已复核通过。最终未发现明确需求缺口。

两条审计轴分别完成，不以测试通过替代源码审计。

## 测试

第三 Agent 独立补充 11 个边界用例，主 Agent 执行全部 20 项浏览器回归。首次运行 16 通过、4 失败：三项暴露批量结果提示未渲染，另一项为首页测试夹具缺少 dashboard 数据。分别修复生产代码和夹具后，最终 **20/20 通过**。

覆盖：标签复用、直达详情、列表与队列刷新、最终与中间节点区别、医院目录缓存、首页待办缓存、详情切单、延迟响应、意见隔离、防重与失败重试、脏数据取消离开、关闭标签取消、查询分页滚动保留、末页回退、批量零/部分/全部成功、重新提交。

- 浏览器日志：`output/approval-final-green.log`。
- 构建日志：`output/approval-refresh-build.log`。
- 编码与 Vue 单文件结构检查通过。
- 测试通过路由拦截全部业务 API，没有修改真实审批数据。覆盖的是前端交互和请求失效机制，不替代真实账号、数据库事务及跨用户通知验收。
- 当前刷新为同一浏览器会话内的主动失效与重新读取，未新增跨用户 WebSocket 推送。
