# 移动定数包整包消耗验收

本阶段仅接入已签收低值实际定数包的整包消耗。继续保留签收及三种拣选方式。散货消耗、部分拆包、高值计费消耗、摄像头扫码、完整离线队列不在本阶段范围。

## 部署与授权

- 后端启用 `SPD_MOBILE_ENABLED=true`，固定 `SPD_MOBILE_SERVER_ID`，测试地址 `http://172.16.2.153:1818/api`。
- 当前SPD版本使用Flyway V97前向补齐缺失的消耗/拣选权限定义和终止回执约束，不恢复停用权限，不添加角色或用户授权。历史V93/V94不重放，现有账号保持不变，由管理员按职责分配。
- 消耗范围沿用电脑端规则：全局用户可在其有效科室库房操作；非全局用户只能操作当前科室。客户端使用独立的 `consumptionWarehouses` 范围。
- Android 9 起支持，包名及签名沿用已有测试版，版本 1.3.0-test.1 / versionCode 5。保留原安装数据进行覆盖升级；未确认回执须先处理。

## 操作与事务

选择整包消耗及科室库房 → 扫实际包码/唯一码（PDA Enter 或手输）→ 核对商品、包内数量 → 勾选整包确认 → 服务器预校验 → 确认提交 → 查看消耗单号、数量、后台金额。

手机不传消耗数量、单价或金额。后端锁定包身份和来源批次，拒绝高值、未签收、已消耗、隔离、批次过期、来源数量不一致和库存不足。消费复用 `QuotaPackageTraceFlowService.consumeByLabelId`，库存扣减、追溯变化、消耗单、结算明细和移动回执在同一事务内完成。

每次操作有持久化 UUID。响应丢失后保留原请求，禁止丢弃并新建，重启后查询原回执或重试原请求。相同 UUID 重试返回原结果，修改内容复用 UUID 拒绝；不同 UUID 消耗同一包只有一次成功。电脑端抢先消耗后手机拒绝重复扣减。

### 1.3.1 原操作恢复修复

凭证过期、服务器重启或查询不到回执时，点击“恢复原操作并重新核对”。三个业务各自的 `POST .../operations/recover` 沿用原业务权限和科室库房范围，在同一事务里锁定原用户/UUID回执：

1. 已有成功或终止回执，直接返回原结果。
2. 原操作仍可执行，仅签发新摘要，不改业务载荷和UUID，不写库存；手机冻结编辑，展示新摘要，由用户确认原操作后提交。再次重启仍按未知结果恢复。
3. 原操作已不可执行，保存 `rejected` 终止回执。手机收到并核对回执身份后可返回列表；所有迟到的同UUID请求均返回该回执，不能再执行业务。

回执状态约束为 pending/succeeded/rejected；当前版本由V97前向补齐，不新增角色授权。恢复与原提交争用相同唯一键和行锁，避免“查询无回执”后直接清除记录带来的迟到写入风险。权限撤销、超时和普通4xx不能代替终止回执，客户端仍保留未知记录。

消耗校验已移到 MobileConsumptionService，Repository只读取身份、批次和余额并按需加锁。未接入的旧明文 Preferences 队列与第二套同步状态机已移除。

## 验证与限制

- `mobile/npm test`：真实状态机单元测试，覆盖确认、存储失败、重复点击、超时、重启和跨账号隔离。
- `scripts/test-mobile-isolated.ps1`：新建独立临时 MySQL，真实 HTTP 登录、拣选、签收、消耗、库存/追溯/结算/回执查询和并发，不修改 ISPD 业务数据。
- `mobile/scripts/consumption-preview-check.js`：Playwright 浏览器 API 夹具，验证页面、PDA Enter、360px布局、重复码、预校验不写入以及响应丢失恢复；不作为原生设备验证。
- APK 构建、lint、签名、API28兼容、zipalign及打包资源一致性检查。真实 Android9/PDA 的覆盖安装、网络切换、进程终止、Keystore 持久化和原生请求仍需设备验收。
- 正式环境使用系统信任的有效 HTTPS 证书。此阶段不涉及安装医院 CA，不绕过 TLS 校验。
