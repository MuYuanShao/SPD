# 证照管理整改说明（2026-09-23）

## 已完成的修复

1. 编辑证照先加载完整详情，提交原ownerId和版本号；服务端保留兼容旧请求的已有主体关联，并重新读取主体的真实编码、名称，不信任手填展示值。历史非合同证照缺少ownerType时，根据licenseType识别原主体类型。
2. 按附件ID、按存储文件名访问均统一检查sys_attachment和license_document的删除标记。文件存在不再意味着可访问，已删除证照的旧文件名链接不能绕过检查。
3. 增加主体搜索接口及页面选择器，支持商品、供应商、厂家；合同可选择所属主体类型。只接受启用、未删除、唯一可定位的主体；ID和编码不一致时拒绝保存。
4. 增加“续证”和“历史”入口；V85迁移增加license_document.revision_no与license_revision。历史以只追加的JSON快照保留证照资料、主体、日期、状态、备注、操作人和当时附件清单。
5. 新增、编辑、续证、上传附件和删除均产生版本记录。旧数据第一次修改前保存原版本；行锁及界面提交的版本号防止并发编辑覆盖。续证保留同一证照ID，不允许换主体；新到期日必须晚于原到期日且不早于今天。

## 已确认并实现的到期联动

| 环节 | 处理规则 |
|---|---|
| 新品准入提交、重新提交、最终生效 | 检查关联主体证照；申请自身注册证有效期已过期时也拒绝 |
| 采购草稿保存 | 可以保存，便于补齐材料 |
| 采购提交、审批通过、下达 | 每次检查当前关联证照，过期、手动失效或尚未到签发日时拒绝，并指出证照名称 |
| 已下达订单收货、历史结算 | 未增加到期阻断，不回滚历史业务 |
| 证照续证生效 | 下次准入或采购动作重新读取最新有效期，无需手工解除额外锁定 |
| 商品、供应商、厂家主数据启停 | 不因证照日期自动改写主数据启停状态 |

有效期到期当天仍有效；早于当前日期才判定过期。资质更新和信息变更申请仍可用于补正资料，不会因为同一到期规则被全面封死。

采购使用订单实际供应商和商品厂家关联证照。合同只在合同编号与商品当前合同编码相符时参与校验，避免其他历史合同误拦截。关联ID优先；旧证照只有主体编码时按准确编码兼容匹配。无法定位主体的旧证照不会被任意套到其他对象，应通过编辑补齐关联。

证照管理不自动覆盖商品主数据中的注册证字段；商品属性修改仍走原审批流程。新增准入申请中填入的注册证有效期需要与实际资料一致。

## 续证与附件操作

- 在证照列表点击“续证”，原主体保持不变，填写延长后的有效期，保存后形成新版本。
- 续证保留已有附件，可以保存后在“附件”中追加新证照文件；每次上传也记录版本。历史版本保留当时的附件清单，不因后来追加文件而改变。
- “历史”可查看旧编号、旧有效期、主体及操作人，直接阅览当时的图片或PDF。
- 图片与PDF仍保存在配置的磁盘目录，数据库存元数据与关联。删除仍为软删除；历史版本保留，但被删除证照附件不再允许通过下载接口读取。
