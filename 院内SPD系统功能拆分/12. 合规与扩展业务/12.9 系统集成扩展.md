# 12.9 系统集成扩展

> 所属模块：12. 合规与扩展业务
> 来源：院内SPD系统产品需求文档.md

## 12.9.1 功能概述

补全 SSO 单点登录、LDAP/AD、微信/钉钉/企微、通知中台、HIS EMPI 患者主索引、LIS/HRP/ERP 对接、省/国家监管平台对接、审计日志七要素标准等系统集成节点，与第 2 章系统架构、第 9 章接口规范形成完整的对外集成能力。

## 12.9.2 功能架构

```
系统集成扩展
├── 单点登录 SSO
│   ├── CAS / OAuth2 / SAML
│   ├── LDAP / AD 集成
│   └── 双因子认证 2FA
├── 即时通讯集成
│   ├── 微信公众号 / 服务号
│   ├── 钉钉
│   └── 企业微信
├── 通知中台
├── HIS 集成
│   ├── EMPI 患者主索引
│   ├── HIS 计费回写
│   ├── HIS 手术单同步
│   └── HIS 患者档案对接
├── LIS / HRP / ERP 对接
├── 监管平台对接
│   ├── 国家不良事件监测平台
│   ├── 国家 / 省级 UDI 上传
│   ├── 省级集采平台
│   └── 医保局对接
└── 审计日志七要素标准
```

## 12.9.3 SSO 单点登录

支持多种 SSO 协议，满足医院已有 IAM 体系：

| 协议 | 适用场景 |
|------|----------|
| CAS 3.0 | 大多数医院通用 |
| OAuth 2.0 | 现代 Web / 移动应用 |
| SAML 2.0 | 集团企业级 SSO |
| OIDC（OpenID Connect） | 含身份信息的 OAuth 扩展 |
| JWT Token 互信 | 简易内部互信 |

| 字段 | 必填 | 说明 |
|------|------|------|
| SSO 配置编号 | 自动 | SSO + 序号 |
| 协议类型 | 是 | 见上 |
| IdP 地址 | 是 | 身份提供方 URL |
| Client ID / App Key | 是 | - |
| Client Secret / App Secret | 是 | 加密存储 |
| 回调地址 | 是 | - |
| 用户映射规则 | 是 | IdP 用户 → SPD 用户的字段映射 |
| 自动开户 | 是 | 是否首次登录自动创建 SPD 账户 |
| 默认角色 | 是 | 自动开户时的默认角色 |
| 状态 | - | 启用 / 停用 |

**双因子认证 2FA：**
- 短信验证码
- TOTP（Google Authenticator / 微信令牌）
- U-Key / CA 证书
- 生物识别（指纹 / 人脸，移动端）
- 适用范围：高敏操作（付款、删除、权限授予、医保结算等）必须 2FA

## 12.9.4 LDAP / AD 集成

| 字段 | 必填 | 说明 |
|------|------|------|
| LDAP 配置编号 | 自动 | LDAP + 序号 |
| 服务器地址 | 是 | LDAP / AD URL |
| 端口 | 是 | 默认 389 / 636（LDAPS）|
| 加密 | 是 | 无 / SSL / TLS |
| 绑定 DN | 是 | 系统账户 |
| 绑定密码 | 是 | 加密存储 |
| 搜索 Base | 是 | 用户搜索根 |
| 用户对象类 | 是 | 默认 inetOrgPerson / user |
| 用户属性映射 | 是 | uid / mail / cn / displayName |
| 同步策略 | 是 | 实时 / 定时 / 手动 |
| 同步周期 | 否 | 定时模式必填 |

**同步策略：**
- 实时：登录时实时校验
- 定时：每日 / 每小时同步用户列表
- 手动：管理员手动触发

## 12.9.5 微信 / 钉钉 / 企微集成

| 平台 | 集成场景 |
|------|----------|
| 微信公众号 | 公众号菜单、模板消息、扫码登录 |
| 微信小程序 | 移动审批、查询入口 |
| 钉钉 | 单点登录、待办推送、审批集成 |
| 企业微信 | 内部沟通、待办推送、审批集成 |
| 飞书 | 类似企微 |

| 字段 | 必填 | 说明 |
|------|------|------|
| 集成平台 | 是 | 见上 |
| AppID / CorpID | 是 | - |
| AppSecret / CorpSecret | 是 | 加密存储 |
| 消息模板 ID | 是 | 各类业务对应的模板 |
| 已绑定用户数 | 自动 | - |
| 启用功能 | 多选 | 登录 / 审批 / 通知 / 扫码 |

**审批同步：** SPD 审批节点同步到钉钉 / 企微待办，钉钉 / 企微完成审批后回写 SPD。

## 12.9.6 通知中台

抽象统一的多渠道通知能力：

```
业务模块
   ↓
通知中台 API（统一接口）
   ↓
路由分发
   ↓
[短信] [邮件] [APP 推送] [钉钉] [企微] [微信] [系统消息] [电话]
```

| 字段 | 必填 | 说明 |
|------|------|------|
| 通知模板编号 | 自动 | TZ + 序号 |
| 模板名称 | 是 | - |
| 业务类型 | 是 | 审批待办 / 召回告警 / 资质到期 / 库存预警 等 |
| 默认渠道 | 是 | 多选 |
| 渠道优先级 | 是 | 失败后降级顺序 |
| 模板内容 | 是 | 支持变量占位 |
| 静默期 | 否 | 避免重复打扰，如 30 分钟内同主题不重发 |
| 紧急级别 | 是 | 一般 / 重要 / 紧急 |
| 接收人规则 | 是 | 角色 / 用户 / 自定义 |

**降级策略：** APP 推送失败 → 短信 → 电话（紧急级别）。

## 12.9.7 HIS 集成

| 接口 | 方向 | 说明 |
|------|------|------|
| EMPI 患者主索引 | HIS → SPD | 患者基础信息（含 ID / 姓名 / 身份证 / 住院号 / 床位） |
| 手术单推送 | HIS → SPD | 排班手术单同步给 SPD（与 8.8.7 临时单合并联动） |
| 计费回写 | SPD → HIS | 高值耗材使用、消耗、押金等费用项推送至 HIS 计费 |
| 患者档案查询 | SPD → HIS | 查询历史病案、过敏史、植入史 |
| 医生人员同步 | HIS → SPD | 医生 / 护士基础信息 |
| 病案同步 | HIS → SPD | 出院病案号、ICD-10 / DRG / DIP 编码（用于 12.7.5 / 12.7.8） |

**通信协议：** RESTful JSON / WebService SOAP / HL7 FHIR（推荐）

**异常处理：**
- 网络断开：本地队列缓存，恢复后补发
- HIS 不可用：降级到本地手工录入，事后核对
- 数据不一致：每日定时核对，差异行人工确认

## 12.9.8 LIS / HRP / ERP 对接

| 系统 | 对接内容 |
|------|----------|
| LIS（检验）| 试剂消耗自动回写、检验项目-试剂对照、试剂效期联动 |
| HRP（医院资源规划）| 资产、人力、财务的横向同步 |
| ERP（金蝶 / 用友 / SAP）| 凭证生成、应付应收、银行回单 |
| OA（钉钉 / 企微 / 用友 OA）| 审批流集成、公文流转 |
| PACS（影像）| 高值耗材植入影像关联（仅高值场景） |

## 12.9.9 监管平台对接

| 平台 | 对接内容 | 频率 |
|------|----------|------|
| 国家不良事件监测平台 | 不良事件上报（关联 8.6.6 / 12.5.4）| 实时 |
| 国家药监局 UDI 数据库 | 三级 / 二级 UDI 上传 | 入库即上报 |
| 省级集采平台 | 中标结果同步、采购量上报 | 实时 |
| 国家卫健委医院资源系统 | 医院基础信息、耗材使用统计 | 月度 |
| 省级医保局平台 | 医保耗材结算、DRG / DIP 病种成本上报、驳回处理 | 实时 |
| 海关 / 检验检疫（进口耗材）| 进口耗材报关数据同步 | 按批次 |
| 应急管理 / 战略储备平台 | 紧急物资库存上报 | 月度 + 应急 |

**安全要求：**
- 所有监管平台对接须使用国密算法 SM2 / SM3 / SM4
- VPN 专线 + 数字证书双向认证
- 关键操作纳入区块链存证（可选）

## 12.9.10 审计日志七要素标准

所有关键操作必须记录七要素，方便审计追溯：

| 要素 | 字段名 | 必填 | 说明 |
|------|--------|------|------|
| Who（人） | user_id / username | 是 | 操作人 |
| When（时） | event_time | 是 | 精确到毫秒 |
| Where（地） | client_ip / location | 是 | IP + 地理位置（可选）|
| What（事） | event_type / biz_type / biz_id | 是 | 业务对象 |
| How（手段） | event_action | 是 | CREATE / UPDATE / DELETE / VIEW / EXPORT / APPROVE 等 |
| Why（原因） | event_reason | 否 | 用户填写或系统自动 |
| Result（结果） | event_result / before_value / after_value | 是 | 成功 / 失败 + 变更前后 JSON |

**审计日志独立存储：**
- 独立日志库（不与业务库混合）
- 防篡改：行级哈希 + 链式追加
- 留档期限：≥ 5 年（关键业务）/ ≥ 10 年（医保 / 不良事件）
- 审计员只读权限，禁止删除 / 修改
- 支持按七要素任意维度组合查询

| 关键操作场景 | 必须记录 |
|--------------|----------|
| 用户登录 / 注销 | Who / When / Where / Result |
| 权限授予 / 撤销 | Who / When / What / Result |
| 业务数据变更 | 全要素 + before/after |
| 敏感数据导出 / 打印 | 全要素 + 数据范围 |
| 召回 / 不良事件 | 全要素 + 时序 |
| 医保结算 | 全要素 + 金额校验 |
| 财务月结 / 反结 | 全要素 + 多人复核 |

## 12.9.11 安全运行期支撑

安全运行期支撑用于承接 PHI 加密、KMS/Vault 密钥引用、审计双写、哈希链和签名验签诊断能力。

| 能力 | 要求 |
|------|------|
| PHI 字段保护 | 患者姓名、证件号、病案号、诊断等字段采用字段级加密，检索字段使用 HMAC Hash |
| KMS / Vault | 明文密钥不得落库，仅保存 `kid`、`key_ref`、算法、状态和轮转信息 |
| 审计双写 | 关键审计日志写入主审计表后进入双写队列，失败可重试、可告警、可追溯 |
| 签名验签 | 审计日志记录 `signing_kid`、签名算法和哈希链信息，支持运行期验签诊断 |
| API 契约 | KMS 与审计运行期诊断接口分别见 `docs/api/paths/kms.yaml`、`docs/api/paths/audit-runtime.yaml` |
