# SPD 与 MCP 供应链对接产品需求文档

**版本** v0.6 · 完整评审稿  
**日期** 2026 年 11 月 25 日  
**评审对象** 院方耗材管理、采购、库房和财务，供应商运营及双方研发、测试、运维

## 1. 背景与目标

院方在 SPD 完成医院目录准入、采购、收货验收和结算。供应商在 MCP 维护商品证照、查看医院订单、申报供货和核对账单。双方通过统一的医院、供应商及商品映射共享业务单据，减少重复录入，并能从验收、入库和结算结果追溯到原订单、采购明细和供货批次。

业务顺序为 **医院建档与供应商绑定 → 商品准入与目录映射 → 采购计划及订单 → 供货申报 → 收货验收入库 → 结算、对账与发票**。

SPD 负责院内目录、采购订单、验收入库和结算结果。MCP 提供供应商商品资料、供货申报及对账协同入口。同步回执确认接收结果，审批、验收、结算和付款分别按院内业务状态判断。

## 2. 用户与职责

| 用户 | 主要职责 |
|---|---|
| MCP 机构管理员 | 创建医院机构和对接实例，维护医疗机构编码，授权供应商绑定 |
| 医院机构及目录管理员 | 审核供应商身份变更，处理绑定冲突，审批目录并确认商品映射 |
| 院方采购员 | 制定采购计划，核对订单拆分、供货占用和剩余可收数量 |
| 供应商商品及供货人员 | 提交商品证照、补充映射资料、按订单批次申报供货及跟踪验收 |
| 院方库房验收员 | 核对实物、批次和效期，确认质检、验收及退货结果 |
| 院方财务及供应商对账员 | 核对结算和发票，提交或处理差异。院方财务负责关闭财务差异 |
| 双方运维 | 管理鉴权、同步诊断、告警及授权重发 |

## 3. 机构开户、医院绑定与供应商身份

### R00 · 开户和绑定

**能力状态**。MCP 已有医院实例配置和供应商绑定，SPD 已能向预配置的 MCP 实例上传供应商和厂家资料。双端发起开户、统一查重、医院审核和结构化绑定回执纳入新增范围。

**发起方向**。SPD 新建供应商并选择医院后向 MCP 上传。MCP 新建供应商并选择已授权医院后向对应 SPD 下发。任一端发起即可，接收端按统一规则匹配并返回结果。各端独立开通本端账号和权限。

| 校验顺序 | 条件 | 接收结果 |
|---|---|---|
| 1. 校验医院 | 医疗机构编码唯一匹配且与授权目标实例一致 | 复用医院，返回「机构已创建」、医疗机构编码和接收端医院标识，发起端保存映射。 |
| 1. 校验医院 | MCP 未查到医疗机构编码 | 拒绝 SPD 本次提交的该医院全部数据，逐条提示「MCP没有该医疗机构，请到MCP新增。」由 MCP 管理员建档后重新发送。 |
| 1. 校验医院 | 编码缺失、重复，或与目标实例不一致 | 拒绝，返回具体原因。MCP 下发只允许路由到编码相符且已授权的 SPD 实例。 |
| 2. 校验供应商 | 同一医院下名称及统一社会信用代码均一致，且唯一命中 | 复用供应商档案，建立或复用供货关系，返回「供应商已创建」和供应商标识。 |
| 2. 校验供应商 | 同一医院下名称及统一社会信用代码均未命中，且无现有绑定或法人主档冲突 | 新增供应商并绑定该医院，返回「供应商新建成功」。 |
| 2. 校验供应商 | 同码不同名、同名不同码、命中多条、跨院法人主档复用或已有映射冲突 | 进入医院审核的变更流程。审核通过后更新档案或建立供货关系。 |

正式开户必填统一社会信用代码。供应商名称去除首尾空白后精确匹配。供应商可从 MCP 提交身份变更，SPD 也可发起变更，已生效的名称、法人身份和对应关系须经医院审核后才能修改。通过后由发起链路向对端同步生效结果，历史业务保留原引用。不同医院分别建立供货关系并隔离可见数据。

**传输与回执**。发起端登记待同步记录，经鉴权 HTTPS 接口发送请求标识、来源系统、医疗机构编码、医院名称、供应商编码、名称和统一社会信用代码。接收端先校验医院，再处理供应商和绑定，分别返回处理状态、两端标识及失败原因。医院未建档时整批拒绝，不保存该批供应商及业务单据。重复或双端并发发起只产生一条有效关系。

**展示节点**。SPD 拟在「系统配置 → 系统集成 → MCP-UI 对接」展示医院映射，在「基础数据管理 → 供应商厂家管理」展示供应商对接状态及变更申请。MCP 在「系统设置 → SPD 对接实例」及实例供应商绑定入口查看机构关系，拟在「采购对接 → 同步记录」展示开户及变更回执。

医院映射完成后才启用该院业务对接。供应商查看目录、订单、验收或结算，还需具有该院的有效供货关系及相应功能权限。[一期对接契约](../../../SPD-MCP-UI/imports/spd-pr-phase1-contract.md) · [供货绑定校验](../reviews/2026-10-30-mcp-supply-receiving-acceptance.md)

## 4. 商品、证照与医院目录

### R01 · 双向目录协同

| 环节 | R01-A · MCP 商品及证照下发 SPD | R01-B · SPD 自建医院目录上传 MCP |
|---|---|---|
| 能力状态 | 已有下发及接收能力 | 拟新增独立上传、接收及查询 |
| 数据来源 | MCP 已保存的供应商商品、关联证照及真实附件 | SPD 本地申请最终审批后生效的医院目录商品，以 `product` 为准，保留来源审批单号及版本 |
| 发送方式 | 供应商发起下发。网络重试沿用原请求，修改资料后发送新版本 | 最终审批生效后在本地事务登记同步事件，提交后按医院实例异步发送完整商品版本 |
| 接收方式 | SPD 校验来源及版本，进入新品、信息、资质、价格或启停审批。审批生效后更新医院目录 | MCP 校验医院、租户及供应商关系，按医院实例和医院商品标识保存。已有映射则关联，缺映射标为待匹配 |
| 展示节点 | SPD「基础数据管理 → 商品目录 → 待审批目录」，生效后在「医院目录」查看 | MCP 拟新增「采购对接 → 医院目录」，支持查询商品编码、名称、规格、基本单位、厂家、注册证号、启停、映射和同步状态 |

SPD 自建目录的条目、采购价及获授权证照仅对该医院下对应供应商开放。相同规则适用于列表、详情、导出及附件下载。建议医院目录管理员负责最终确认商品映射，供应商可补充本企业商品编码、规格、单位及证照。缺少映射时提示处理人，关联单据按异常规则处理。

待审批、退回或驳回的申请不上传为有效目录。更新、批准停用及证照状态变化按新版本同步，旧版本不覆盖当前结果。同名商品不自动合并。MCP 下发成功仅表明资料进入 SPD 待审批目录，医院采购资格以院内审批结果为准。[商品及证照规则](../mcp-phase1-integration.md) · [现有上传范围](../../backend/src/main/java/com/hospital/spd/integration/McpUploadJob.java)

## 5. 采购、供货、验收与库存

### R02 · 采购计划与订单

来源为 SPD 实际保存的采购计划、订单及明细。一张混合计划可包含高低值商品和多个配送商，最终审批后按配送商拆分订单。发送真实订单号、明细 ID、共同计划来源、供应商、商品、单位、数量、单价、金额和状态。

MCP 按医院及供应商范围接收，并在「采购对接 → 医院计划与结算」、现有「上传采购订单」及采购订购报表展示相关数据。明细缺少商品映射时提示失败，补齐后恢复。试点验证两家配送商生成各自订单、保留同一来源计划且可见范围隔离。[采购计划与结算方案](2026-10-29-mcp-purchase-plan-settlement-integration.md) · [混合采购流程](../business/SPD-MCP业务操作思维导图.md)

### R03 · MCP 供货申报与回执

供应商在 MCP「采购对接 → 医院计划与结算 → 医院订单供货」选择医院订单，查询 SPD 剩余可收量，按明细填写供货单号、院内库房、数量、批号、生产日期和有效期。MCP 保存申报并通过持久化发送任务回传。SPD 校验绑定、采购明细、商品、单位、日期和剩余数量，成功后创建有 MCP 来源标识的待验收草稿。

待验收草稿计入数量占用。并发供货不得超过剩余可收量。导入草稿保留采购来源及申报数量上限。院方在 SPD「收货验收」处理实物和质检，仅合格量审核入库。供应商在原 MCP 供货单刷新 SPD 状态，查看草稿、验收或拒收回执、实际验收量和原申报批次。重复请求不得重复建单或入库。[供货验收记录](../reviews/2026-10-30-mcp-supply-receiving-acceptance.md)

### R04 · SPD 自建采购收货验收单上传 MCP

| 环节 | 规则 |
|---|---|
| 数据来源 | SPD 已保存的 `receiving_order`、`receiving_order_item` 及关联的原采购订单、采购明细、供应商和库房。来源字段含收货单号、单据日期、实际收货日期、状态、商品编码、单位、批号、收货量、合格量、不合格量和原因。无采购订单的临时收货不纳入本期履约对接。 |
| 当前发送方式 | 启用上传总开关及二期同步后，SPD 按轮次先发采购订单，再通过 `POST /api/integration/instances/{实例ID}/phase2/receiving` 发送完整收货验收单。当前默认调度间隔 60 秒，可配置。 |
| 目标发送方式 | 保存草稿、审核通过或拒收时登记同步事件，按同一收货单号和业务版本异步发送。发送流程遵循 R07 上游依赖及故障恢复规则。 |
| MCP 接收 | 校验医院实例、订单、供应商、商品、单位、采购明细和累计验收量，整单通过后保存为 `receiving` 对接记录。重复和旧版本忽略。 |
| 展示节点 | MCP「采购对接 → 履约与库存 → 履约单据查询 → 收货与验收」，按单号查看最新状态及原采购明细、批号和质检数量。接收失败在「同步记录」查询。 |

用 SPD 自建采购收货单分别验收草稿、审核通过和拒收。草稿可见但不计入已验收量，拒收不产生合格入库。MCP「医院订单供货」的回执用于 MCP 发起的供货申报。SPD 自建采购收货单的展示入口是「收货与验收」。[SPD 验收取数](../../backend/src/main/java/com/hospital/spd/integration/McpPhase2Source.java) · [二期接收与展示契约](../../../SPD-MCP-UI/imports/spd-pr-phase2-contract.md)

### R05 · 采购入库与批次库存

采购入库取自 SPD 的不可变采购入库事件，并通过库存批次和验收明细追溯原单。数量和金额取来源事件，历史回填值单独标记。MCP 在「履约单据查询 → 采购入库」查询，累计入库量须与对应合格量一致或低于该数量。

批次库存按已映射商品生成完整快照，沿用定时发送。MCP 校验通过后整体替换上一版本，空快照清空旧余额。发现商品或批次分摊缺失时记录失败，保留上一有效快照。在 MCP「履约与库存 → 批次库存与效期」展示，订单执行与履约报表分别统计验收与入库。[二期规则](../mcp-phase1-integration.md#第二期收货入库和库存同步)

## 6. 结算、对账与发票

### R06 · 结算及供应商反馈

SPD 发送真实结算主单、明细和来源依据，保留四位来源金额和已知金额口径。结算生成、确认、调整或取消均按版本同步，反消耗后保留历史。大单分片齐备并完成校验后再发布新版本。

MCP「采购对接 → 医院计划与结算」展示所属供应商账单。供应商可提交确认或异议反馈，并按规则撤回自己的反馈。院方财务负责跟进、确认和关闭差异。反馈仅用于协同，院内结算确认、红冲及付款按 SPD 财务流程办理。高值耗材由 SPD 收到 HIS 等来源计费后记录使用并扣库存，科室领用、签收和消耗分别记录。[结算及反馈边界](2026-10-29-mcp-purchase-plan-settlement-integration.md) · [业务操作大纲](../business/SPD-MCP业务操作思维导图.md)

### R06-A · 税口径、部分开票与历史回填

- **币种及税口径**。对接币种为人民币 CNY。采购、验收和结算同步时税口径可留空。填写发票资料，或结算确认后上传发票时，税口径及发票要求的税务字段为必填。历史缺失值保留待补状态。
- **部分开票**。同一结算单可关联多张发票。按有效审核的分摊金额计算累计已开票额、剩余待开票额，并在提交环节校验累计占用和剩余额度。作废或红冲后释放对应额度，并保留关联记录。
- **差额与尾差**。发票额小于结算总额且在余额内可按部分开票处理。累计超额，或申请全部开票完成时仍有差额，由系统提示差额并转财务核对。双方先确认可比较的金额口径，再判断差异。建议最后一张票由院方财务确认合理舍入尾差并记录依据，超额或业务差异按发票补正或结算调整流程办理。
- **历史回填**。建议按医院、供应商、业务类型及起止日期审批并分批回填，优先处理已确认而待开票或待对账的结算单。保留历史金额和已知税口径，缺失字段待补。实际范围、尾差阈值和调整权限由试点医院财务确认。

## 7. 事务触发、同步时效、告警及待办

### R07 · 同步机制

订单生效、收货验收保存或状态变化、结算生成或调整时，在**同一笔本地业务事务**保存业务结果和待同步事件。事务提交后立即异步尝试发送。接收端在本地事务内保存当前有效版本及对应业务待办，处理后返回回执。发起端业务事务独立于远端回执，网络故障时可从持久化事件恢复。

定时任务负责扫描待发送事件、执行到期重试、处理超时告警以及发送完整库存快照。现有二期定时业务扫描作为过渡方式，切换时应避免同一对象由新旧链路重复触发。发送和接收以消息标识、来源对象和版本做幂等控制。依赖顺序为机构及供应商绑定、商品映射、采购订单、收货验收、采购入库。业务版本或迟到回执不得覆盖更新结果。

| 对象 | 目标触发方式 | 建议试点同步目标 | 建议告警阈值 |
|---|---|---:|---:|
| 采购订单 | 生效后事务登记，提交后立即尝试 | 5 分钟 | 15 分钟 |
| 收货与验收 | 保存、审核或拒收后事务登记，提交后立即尝试 | 5 分钟 | 15 分钟 |
| 批次库存 | 定时完整快照 | 15 分钟 | 30 分钟 |
| 结算 | 生成、确认、调整或取消后事务登记，提交后立即尝试 | 15 分钟 | 30 分钟 |

同步时长从来源状态提交且符合该对象发送条件起算，到接收端可查询为止。因机构、映射或单据错误阻断的记录进入异常待办，保留阻断时间。上述时间为试点建议值。

### R07-A · 三条失败处理规则

1. **有限自动重试。** 网络超时或目标服务暂不可用时，首次失败后最多自动重试 **5 次**，每次失败后依次等待 **1、5、15、30、60 分钟**。回执丢失时优先按消息标识查询。仍未知时用原消息标识及原报文重发，接收端返回原处理结果或按幂等规则处理。
2. **业务错误转待办。** 医院未建档、供应商未绑定、商品未映射或单据校验错误时立即停止自动重试，按失败原因分配业务待办。补齐外部依赖且报文不变时可授权重发原消息。修改业务内容时生成新版本。医院未建档按 R00 逐条报错。
3. **达到上限后人工恢复。** 自动重试耗尽后进入「待人工处理」，停止自动发送并保留失败原因、历史次数和回执，生成运维待办。授权人员可单条或批量重发。若同一单据的更新版本已成功接收，旧失败版本标为「已被替代」，停止重发。

**告警阈值和重试上限分别配置与判断。** 达到时长阈值即告警，仍有次数且属于临时故障时继续重试。耗尽次数即停止自动发送，即使尚未达到告警阈值。相同消息的多次失败更新同一有效告警，确认同步成功后自动关闭。自动尝试次数、人工重发和告警时间分别记录。

### R07-B · 登录待办与责任

| 接收人 | 登录后的待办 | 关闭条件 |
|---|---|---|
| MCP 供应商 | 对应医院的自家待供货、拒收待补供、商品待补资料、结算待核对和发票待提交 | 接收端按最新业务状态更新，处理完成后关闭 |
| SPD 院方业务人员 | 供应商身份变更待审批、商品映射待确认、待验收、结算异议待处理 | 审批、确认、验收或财务关闭后更新 |
| 双方运维 | 超时、临时故障、重试耗尽待处理 | 确认接收成功后关闭。发送端负责发送和重发，接收端负责接收故障，业务负责人补齐业务资料 |

待办预先保存，登录时按医院、供应商和角色权限读取，展示来源单号、原因和处理入口。同一业务对象的同类有效待办去重，技术排障分配运维，供应商仅看到本企业需要处理或知悉的事项。日志记录来源对象、版本、状态和原因，账号凭证及密钥由各端配置管理。

## 8. 试点异常业务建议

| 场景 | 建议规则 |
|---|---|
| 部分拒收后补供 | 允许从原订单明细发起新补供，关联原拒收记录。可补量为采购量扣除累计合格验收量及仍占用的未结束供货量，SPD 提交时再次校验。例如采购 10 支、合格 8 支且无未结束占用，可补供 2 支。 |
| 已入库退货 | 在原批次关联、库存扣回和结算影响确认后启用。仅回传 SPD 已确认的独立退货单及原订单、收货、入库和批次关联。是否恢复可补供量由院方采购决定。现有二期支持 MCP 接收及报表，SPD 主动上传纳入试点待确认。 |
| 旧供货单更正 | 未生成 SPD 草稿时更正并重新提交。已生成草稿未审核时，由院方撤销或退回草稿、释放占用后提交更正版。已入库时走退货、冲销或补供。保留原单、原因及版本关联。 |

建议先试点部分拒收补供和未审核供货单更正，再启用已入库退货回传。

## 9. 验收与上线

| 验收场景 | 通过标准 |
|---|---|
| 双端开户 | 已有机构按编码复用。MCP 无医院时 SPD 整批上传被拒绝并逐条收到指定提示。正式开户缺统一社会信用代码失败。同院同名同码复用，身份冲突走医院审核，并发提交不重复绑定。 |
| SPD 自建目录 | 审批生效后在 MCP 查到对应条目，验证价格、证照和下载隔离、映射确认、停用及旧版本处理，并完成关联订单和验收联调。 |
| 混合采购与分批供货 | 两家配送商独立订单可追到同一计划，正确校验并发剩余量。供货回执、批次和合格量可核对。 |
| SPD 自建验收 | 查询草稿、审核通过及拒收版本。原采购明细、日期和数量一致，只有合格数量入库。 |
| 部分开票与差异 | 两张以上发票可分摊同一结算单，超额拦截，作废或红冲后余额正确。税口径的必填时点正确，财务可关闭已处理差异。 |
| 断网与回执丢失 | SPD 业务事务可正常提交。链路恢复后补传，原标识重试无重复业务结果及待办。 |
| 重试、告警与待办 | 验证达到告警阈值但仍能重试、达到重试上限但尚未告警、业务错误立即转待办、手动重发后关闭告警，以及跨供应商待办隔离。 |

建议上线门槛为试点单据来源全链路可追溯，重复建档、重复入库、超量入库和越权访问成功数均为 0，失败可定位并验证恢复。启用前核对双方版本、迁移、功能开关、实例密钥、供应商绑定及商品映射。

历史记录包含 **145 项隔离环境双端联调通过、49 项供货专项检查通过**及 1001 行结算分片验证。这些成绩用于评估现有链路。机构双端开户、SPD 自建目录上传、事务触发、待办、有限重试以及部分开票要求须按本稿新增场景验收。[双端复测](../reviews/2026-10-30-mcp-phase3-retest.md) · [供货验收](../reviews/2026-10-30-mcp-supply-receiving-acceptance.md) · [结算验收](../reviews/2026-10-30-mcp-phase3-acceptance.md)
