# 6.1 UDI追溯

> 所属模块：6. 专项管理模块
> 来源：院内SPD系统产品需求文档.md

## 6.1.1 功能概述

UDI（Unique Device Identification，医疗器械唯一标识）是医疗器械产品的"身份证"，是实现医疗器械精准识别和全程追溯的基础。国家药监局要求第三类医疗器械全部实施UDI管理。

## 6.1.2 UDI组成

```
UDI = DI（器械标识） + PI（生产标识）

示例：(01)06901234567890(11)260427(17)280427(10)ABC123(21)XYZ789

DI（器械标识）：(01)06901234567890
  - (01) = GTIN标识符
  - 06901234567890 = 14位GTIN码

PI（生产标识）：
  - (11)260427 = 生产日期 2026-04-27
  - (17)280427 = 有效期至 2028-04-27
  - (10)ABC123 = 批次号
  - (21)XYZ789 = 序列号
```

## 6.1.3 UDI数据元素

| 数据标识符 | 含义 | 格式 | 示例 |
|------------|------|------|------|
| (01) | GTIN | 14位数字 | 06901234567890 |
| (10) | 批次号 | 1-20位字母数字 | ABC123 |
| (11) | 生产日期 | YYMMDD | 260427 |
| (17) | 有效期 | YYMMDD | 280427 |
| (21) | 序列号 | 1-20位字母数字 | XYZ789 |
| (71) | 生产国家 | 3位数字 | 156 |

## 6.1.5 UDI验证规则

| 验证项 | 规则 | 错误处理 |
|--------|------|----------|
| GTIN格式 | 14位数字 | 提示"GTIN格式错误" |
| GTIN存在性 | 必须存在于商品目录 | 提示"未找到对应商品" |
| 生产日期 | 不能晚于当前日期 | 提示"生产日期异常" |
| 有效期 | 必须晚于当前日期 | 提示"商品已过期" |
| 批次号 | 1-20位字母数字 | 提示"批次号格式错误" |
| 序列号 | 1-20位字母数字 | 提示"序列号格式错误" |

## 6.1.7 UDI/唯一码生命周期

高值耗材和冷链试剂不进入定数包管理，必须以验收入库自动生成的唯一码、UDI 或人工补录的 UID 作为最小管控对象。唯一码在同一租户内必须唯一，不允许删除后复用；确需更换标签时，必须生成新旧码关联关系和更换留痕。

| 状态 | 含义 | 进入来源 | 退出来源 |
|------|------|----------|----------|
| 待验收 | 已到货但未完成验收 | 采购到货、供应商寄售到货 | 验收通过、验收拒收 |
| 已入库 | 已完成验收并建立追溯码 | 扫码验收、人工 UID 补录 | 上架、隔离、退供应商 |
| 在库 | 可被出库、调拨或手术备货 | 上架确认、退回复核通过 | 锁定、出库、召回、报损 |
| 锁定 | 已被业务单据占用 | 手术备货、科室请领、调拨申请 | 出库、取消、超时释放 |
| 已出库 | 已离开当前库房 | 配送出库、手术领用出库 | 科室签收、退回、使用确认 |
| 已使用 | 已与患者、手术或医嘱绑定 | 术中扫码、科室使用确认 | 反记账、质控追溯 |
| 已退回 | 实物退回并待复核 | 科室退回、手术未用退回 | 转在库、隔离、退供应商 |
| 隔离 | 不可用，待质控判定 | 冷链异常、召回命中、包装破损、退回待判定 | 转在库、报损、销毁、退供应商 |
| 已召回 | 被质量事件或供应商召回命中 | 召回通知、监管要求 | 退供应商、销毁、关闭召回 |
| 已报损/销毁 | 实物不可再用 | 质控判定、过期、破损 | 归档，不允许再次流转 |

**管控规则：**
- 每次状态变化都必须生成唯一码事件流水，记录操作人、时间、来源单据、前后状态和院区/库房/科室。
- 高值耗材使用时必须关联患者、手术、医生、科室和收费/医嘱同步结果；未完成关联时不得关闭使用单。
- 冷链试剂唯一码必须能关联温度记录、冷链设备、运输批次和异常处置结果。
- 标签损坏、重贴、人工补录 UID 必须强制留痕，并保留原码、新码、原因和复核人。
- 唯一码库存与财务结算、患者追溯、召回范围以事件流水为准，查询快照只用于展示和性能优化。

## 6.1.8 当前实现基线（2026-07-13）

**实现状态：部分实现。** 当前系统已经形成追溯查询和高值计费闭环，但通用 UDI 解析、国家药监局同步及所有扫码作业尚未全部落地。

已实现：

- `udi_trace_code` 保存 UDI、唯一码、追溯范围、商品、批次、当前位置、科室、患者脱敏信息和当前状态。
- `udi_trace_event` 保存来源业务、位置、科室、操作人、时间、状态和备注，并按事件顺序展示时间线。
- 追溯范围包含 `high_value` 和 `low_value_quota_pack`，分别支持高值耗材和低值定数包。
- 支持按 UDI、唯一码或定数包标签号查看详情；不存在的码返回“追溯码不存在”，不回退到其他记录。
- 高值计费同时提供 UDI 和唯一码时，两者必须命中同一追溯记录；商品编码必须与追溯记录一致。
- 收费记录通过稳定的 `trace_code_id` 外键关联追溯主记录，文本码仅作为业务展示和输入条件。

接口基线：

| 接口 | 用途 |
|---|---|
| `GET /api/udi-traceability/records` | 分页查询追溯记录 |
| `GET /api/udi-traceability/records/{code}` | 按 UDI、唯一码或包标签查询详情和时间线 |
| `GET /api/udi-traceability/summary` | 查询范围和状态汇总 |
| `GET /api/udi-traceability/options` | 查询条件选项 |

验收标准：

- [x] 高值耗材详情返回 `traceScope=high_value`。
- [x] 低值定数包详情返回 `traceScope=low_value_quota_pack` 和包标签信息。
- [x] 不存在的追溯码返回 400 业务响应且不泄露其他患者数据。
- [x] UDI 与唯一码冲突时拒绝计费回调。
- [ ] 完成 GS1/UDI-DI/PI 通用解析和校验规则引擎。
- [ ] 完成国家药监局、供应商 UDI 数据同步及失败补偿。
- [ ] 覆盖入库、上架、盘点、退回、报损等全部扫码写入事件。
