# 8.9 结算与发票扩展

> 所属模块：8. 院内SPD业务扩展模块
> 来源：院内SPD系统产品需求文档.md

## 8.9.1 功能概述

补充消耗结算单、发票节点、付款申请节点等。

## 8.9.2 功能架构

```
结算与发票扩展
├── 消耗结算单
│   ├── 生成消耗结算单
│   ├── 消耗结算单审核
│   └── 消耗结算单查询
├── 发票管理（新发票节点）
│   ├── 新增发票
│   ├── 发票认证
│   ├── 发票匹配
│   └── 发票冲红
└── 付款管理（付款申请节点）
    ├── 付款申请
    ├── 付款审批
    └── 付款执行
```

## 8.9.3 生成消耗结算单

实销实结模式（按科室实际消耗结算给供应商）：

| 字段 | 必填 | 说明 |
|------|------|------|
| 消耗结算单号 | 自动 | XS + YYYYMMDD + 序号 |
| 供应商 | 是 | - |
| 结算周期 | 是 | 月/季 |
| 结算范围 | 是 | 库房消耗 / 手术消耗 / 全部 |
| 消耗明细 | 自动 | 抓取期间内消耗记录（含批号、数量、单价） |
| 应结金额 | 自动 | Σ(数量 × 单价) |
| 含税金额 | 自动 | - |
| 关联反消耗 | 自动 | 自动扣减期内已发生的负数账反消耗 |
| 状态 | - | 草稿 / 待审核 / 已审核 / 已发供应商 / 已确认 / 已开票 / 已付款 |

**生成方式：**
- **自动生成**：定时任务按结算周期触发，按消耗记录生成。
- **手动生成**：财务选择"消耗范围 + 时间段 + 供应商"手动生成。
- **混合**：自动生成草稿 → 财务复核后发出。

**结算取价规则：**

- 普通耗材产生消耗数据时，即固化消耗批次单价并形成供应商应结算事实；月度结算单只是汇总确认载体，不是价格可直接变更边界。
- 定数包拆包整包消耗时，按包内来源系统批次明细生成消耗明细，并固化对应批次单价。
- 验收入库即结算的商品，验收入库后即形成结算事实，后续退货/冲销按原验收入库结算单价反向处理。
- 高值耗材绑定患者并计费后形成计费事实，必须先走计费冲销/退费，再处理 UID 库存状态。
- 反消耗负向记录按原正向消耗记录的单价和金额冲回，不按当前批次单价。
- 批次单价调整不覆盖已消耗、已结算、已计费原单价；已产生事实的数据通过补差、红冲或财务调整处理。
- 采购订单价格只作为订单分析价格。订单完成按数量履约为主，订单价与验收入库批次价差异只进入院内价差记录、复核和分析，不阻断订单关闭，不强制供应商单独确认。

## 8.9.4 新的发票节点

供应商基于消耗结算单或采购入库单开具发票，财务在 SPD 内做发票登记、认证、匹配：

| 字段 | 必填 | 说明 |
|------|------|------|
| 发票编号 | 是 | 唯一 |
| 发票代码 | 是 | - |
| 发票类型 | 是 | 增值税专票 / 普票 / 数电票 |
| 开票日期 | 是 | - |
| 供应商 | 是 | - |
| 关联结算单 | 是 | 多张结算单可对应一张发票 |
| 价税合计 | 是 | 与结算单金额一致 |
| 税额 | 是 | - |
| 认证状态 | 自动 | 已认证 / 待认证 / 认证失败（对接税务） |
| 匹配状态 | 自动 | 完全匹配 / 金额差异 / 数量差异 / 未匹配 |
| 附件 | 否 | 发票影像（PDF/JPG） |

**发票冲红：** 已认证发票如需作废，必须开具红字发票冲销，原发票与红字发票均纳入档案。

## 8.9.5 发票申请付款节点

财务基于已认证、已匹配的发票发起付款申请：

| 字段 | 必填 | 说明 |
|------|------|------|
| 付款申请单号 | 自动 | FK + YYYYMMDD + 序号 |
| 关联发票 | 是 | 一张或多张发票 |
| 申请付款金额 | 是 | 默认 = 发票应付金额 - 质保金 |
| 质保金扣留 | 自动 | 按合同条款 |
| 申请付款日期 | 是 | - |
| 付款方式 | 是 | 银行转账 / 承兑汇票 / 票据贴现 |
| 收款账户 | 自动 | 来自供应商银行账户 |
| 申请理由 / 备注 | 否 | - |
| 附件 | 否 | 合同、入库单、消耗单 |

**付款审批流程：**
```
[财务发起] → [运营管理员审核] → [财务总监审批]
    → [金额>50万：院领导审批] → [出纳执行付款]
    → [回写付款记录、更新结算单状态] → [推送供应商]
```

| 状态 | 说明 |
|------|------|
| 草稿 | 财务编辑中 |
| 待审核 | 已提交，等待审核 |
| 已审核 | 进入审批流 |
| 已审批 | 待出纳执行 |
| 部分付款 | 分期付款时 |
| 已付款 | 全额完成 |
| 已驳回 | 流程中止 |

## 8.9.6 红冲矩阵与跨期处理

已结算数据不得被静默修改。发生定数包反消耗、科室退回、质量召回、价格追溯调整、发票冲红等跨期事项时，系统必须基于当前入账期生成红冲或调整数据，并保留原正向记录与反向记录。

| 业务阶段 | 处理方式 | 审批/复核要求 | 对供应商展示 | 院内查询展示 |
|----------|----------|---------------|--------------|--------------|
| 未生成结算单 | 在原业务期间生成负数消耗/退回记录，重新汇总结算草稿 | 按业务单据配置 | 明细负数行 | 明细 + 定数包数量字段 |
| 已生成未审核结算单 | 结算草稿重新计算，保留重算日志 | 财务或运营复核 | 明细正负行 | 明细 + 定数包数量字段 |
| 已审核/已发供应商未确认 | 当前入账期生成红冲明细，关联原结算单 | 供应商确认或对账复核 | 明细红冲行 | 明细 + 定数包数量字段 |
| 已确认未开票 | 当前入账期生成红冲结算数据，进入下次对账 | 财务复核 | 明细红冲行 | 明细 + 定数包数量字段 |
| 已开票未付款 | 生成发票冲红申请，红冲进入当前入账期 | 财务审批 + 发票复核 | 明细红冲行 + 发票状态 | 明细 + 定数包数量字段 |
| 已付款 | 生成次月红冲结算数据，可形成应付抵扣、退款应收或供应商往来调整 | 财务审批 + 对账确认 | 明细红冲行 | 明细 + 定数包数量字段 |
| 已推送 HIS/医保/财务外部系统 | 不自动改外部结果，生成待外部确认任务，收到冲销回执后关闭 | 接口复核 + 财务确认 | 明细红冲行 | 外部回执状态 + 明细 + 定数包数量字段 |

**展示与入账规则：**
- 推送给供应商的数据只展示明细，不出现定数包总行。
- 院内查询以明细数量、定数包数量、定数包包装数量字段区分，不需要展开为额外总行。
- 红冲数据以当前处理时间确定 `accountingPeriod`，不按原业务发生时间反向改账。
- 一正一反记录都必须保留，红冲记录必须关联原消耗、原定数包事件、原结算单、原发票和审批流程。
- 已结算定数包反消耗审批通过后，先恢复原科室定数包库存，再在当前入账期生成红冲结算数据。
- 对账、月结、发票、付款任一节点已关闭时，后续纠错只能走红冲/调整流程，不允许直接删除或覆盖原记录。
- 批号/效期批量调整不改变金额和结算状态，不生成供应商追溯信息更正通知，不触发已推送供应商数据重推。
