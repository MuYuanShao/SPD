# 目录审批驱动的定数包计价

日期：2026-10-22。状态：已实施。

## 业务口径

模板的套包参考单价等于医院目录最新基本单位采购价乘以包内基本单位数量，金额保留四位小数，使用 HALF_UP。包装换算已由模板保存服务规范为基本单位数量，不重复乘以中包装数量。

医院目录价格只有最终审批通过后才生效。此时在同一业务事务中更新目录价格版本、符合条件套包的当前计价、调价主记录和逐包差额。中间审批、退回、驳回及价格未改变不触发调价。首次准入没有存量套包可调整。

套包来源批次成本、打包预占成本、消耗原始成本、库存事件及已有结算明细均不覆盖。套包新增的 settlement_unit_price 是可结算计价，不是原始成本字段；NULL 表示沿用来源/消耗的原价。

## 调价边界

- 按商品关联所有套包，不依赖当前模板版本，因此旧模板版本生成的有效未结算套包也纳入范围。
- 已拆包、已作废、已终止、已结算的套包不调整。
- 任意已生成结算明细即锁价，包含尚待确认、部分结算和混批中任一来源已结算的情形。
- 使用稳定 trace_code_id、历史科室消耗业务关联以及来源批次的入库结算关联识别结算状态；不能只看标签状态。
- 缺少来源明细的套包不自动调价。
- 存量套包尚无当前计价时，以来源数量乘以来源单价的合计作为调整前金额。后续调价以其当前计价计算差额，连续调整逐次留存。
- 同时修改价格和基本单位会中止该次审批事务，须分开申请并核实包装换算，避免旧数量套用新单位。

## 结算和并发

目录审批、打包确认、扫码消耗及结算生成共享商品行价格锁；多商品结算按商品 ID 顺序获取锁，随后按稳定追溯标识锁定套包。

收货创建、修改、审核以及普通消耗、反消耗也在获取来源或库存锁之前锁定相关商品。结算与补单入口先无锁发现本次商品范围、按商品 ID 升序获取价格锁，再当前读锁定该范围内的来源；并发新增的其他商品留到下次补单，收货单审核期间商品范围变化则回滚并要求刷新。已存在结算明细必须再以当前读确认，不能信任发现阶段的旧快照。

审批读取套包、来源和结算关联使用 MySQL 当前读，防止审批开始时的旧快照漏掉后来提交的新套包或结算。若调价先获得锁，新生成的套包消耗结算读取新计价；若结算先获得锁，该套包在后续调价时保持原价。

科室消耗生成新的供应商结算明细时，对有稳定套包追溯关系或明确历史套包业务关联的数据读取当前套包计价，新结算优先补齐稳定追溯关联；散货、高值和入库结算仍沿用各自业务价格口径。已有结算单不因目录调价重算，需另走撤销重建或差额调整流程。

混批结算先按整包数量计算一次四位 HALF_UP 总额，扣除不可修改的已结金额后，按未结来源数量分摊剩余额度。先向下保留四位，再将 0.0001 尾差按小数余数降序分配，同余数以来源明细 ID 升序决定。全包来源参与分摊，即使本次只结某个供应商，也不会在后续补单时重复舍入。原始来源、消耗成本不改写；来源总数量与包内数量不符，或历史已结金额差异超过合理舍入范围时，停止自动生成并要求走差额调整。

任一联动步骤失败，由外层审批事务整体回滚。审批单号唯一约束和商品价格版本约束防止重复调价。目录价格变更记录即使没有符合条件的存量套包也会保留，影响数量为零。

## 历史与迁移

V95 仅增加价格版本、当前计价字段和调价记录表，不回写历史成本或推断既往审批的价格差额。历史套包在下一次有效目录调价时按上述规则处理；新打包套包按当前已审批目录价初始化，已经参与结算的来源保持原价。

模板列表通过关联 product 动态读取最新参考价，不对旧模板版本的业务内容批量改写。缓存页面重新激活时读取最新数据，过期响应被丢弃；编辑包装数量只影响参考价展示，服务端价格仍由目录和实际数量计算。

## 验证方式

普通测试包括 QuotaPackagePricingServiceTest，以及既有审批、打包、扫码消耗和结算测试。

QuotaPackagePricingMysqlTest 仅在 SPD_PRICING_MYSQL_TESTS=true 时运行，创建随机命名的独立 MySQL 测试库，以 Flyway 应用 V95；退出时仅清理该测试库，禁止使用已有业务库。覆盖连续调整、幂等、回滚、零价、混批锁价、两个方向的并发，以及旧读快照下新套包/新结算的可见性。
