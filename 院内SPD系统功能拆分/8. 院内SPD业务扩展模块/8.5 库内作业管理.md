# 8.5 库内作业管理

> 所属模块：8. 院内SPD业务扩展模块
> 来源：院内SPD系统产品需求文档.md

## 8.5.1 功能概述

补充库内打包/拆包、定数标签状态、出入库查询、盘点单（含手持盘点）等节点。

## 8.5.2 功能架构

```
库内作业管理
├── 库内打包
├── 打包查询
├── 拆包
├── 拆包查询
├── 定数标签状态查询
├── 耗材出入库查询
├── 新增盘点单
└── 手持盘点
```

## 8.5.3 库内打包

中心库或二级库内部对在库物资进行二次打包（区别于 8.3.8 收货打包，库内打包面向已上架在库的库存）：

| 场景 | 说明 |
|------|------|
| 整件转散货后再打包 | 拆零后部分组合打包 |
| 临时手术包 | 即时为某手术配置组合包 |
| 跨货位归集 | 多货位库存合并到一个虚拟包号便于配送 |

| 字段 | 说明 |
|------|------|
| 打包单号 | DB + YYYYMMDD + 序号 |
| 包号 | 唯一二维码 |
| 包内明细 | 商品、批号、数量、来源货位 |
| 打包目的 | 申领出库 / 手术备货 / 临时归集 |
| 状态 | 已打包 / 已拆包 / 已出库 |

## 8.5.4 打包查询

| 维度 | 说明 |
|------|------|
| 按包号 | 查看包内容、状态、流转记录 |
| 按打包人/时间 | 工作量统计 |
| 按关联单据 | 反查申领/手术单关联包 |
| 按状态 | 在库已打包 / 已出库 / 已拆包 |

## 8.5.5 拆包

将"已打包且未发生消耗"状态的包拆解还原为单件库存（适用于：包整体未使用退回、临时归集后未配送、整件转散货等）。已发生消耗的定数包不得通过普通拆包直接还原库存，必须走定数包反消耗或退回重打包流程：

| 操作 | 说明 |
|------|------|
| 扫描包号 | PDA 扫描包号 |
| 拆包确认 | 系统列出包内明细 |
| 库存还原 | 包内每件物品按原批号回库到指定货位（散货回散货位） |
| 拆包原因 | 必填：未使用退回 / 临时拆零 / 包错重打 / 其他 |

## 8.5.6 拆包查询

| 字段 | 说明 |
|------|------|
| 拆包单号 / 原包号 | - |
| 拆包人 / 拆包时间 | - |
| 拆包原因 | - |
| 还原货位 | 每件还原后的货位 |
| 关联手术 / 关联申领 | 用于反查 |

## 8.5.7 定数标签状态查询

每个定数包打包后生成定数标签（条码/二维码），状态全程可追溯：

| 状态 | 说明 |
|------|------|
| 已打包 | 中心库刚打包完毕 |
| 在库 | 已上架到二级库 |
| 已发出 | 配送中 |
| 已签收 | 二级库已签收 |
| 待打印/待贴标 | 已生成定数包库存但标签未打印或未贴标 |
| 已使用 | 已被消耗（拆开使用） |
| 已拆包 | 临时拆解未使用 |
| 已退库 | 退回中心库 |
| 异常 | 丢失 / 损坏 / 过期 |

| 查询字段 | 说明 |
|----------|------|
| 定数标签号 | 主键 |
| 包名 / 适用科室 | - |
| 当前状态 / 状态变更时间 | - |
| 全链路追溯 | 显示每次状态变更记录 |

### 定数包全生命周期与反消耗规则

定数包采用"集团模板 + 院区/科室实例"模型。集团维护标准包族、包模板和商品明细，院区/科室维护适用范围、安全包数、补货阈值、任务评分权重等差异化配置。

**准入边界：**

定数包仅用于非高值耗材和非冷链试剂，不承接包内明细的最高风险属性。高值耗材和冷链试剂根据验收入库自动生成的唯一码或填写的 UDI 进行独立管控，不纳入定数包整包消耗模型。定数包模板发布和新打包时，必须校验包内商品主数据的 `是否定数管理` 字段；只有 `是否定数管理 = 是` 的商品可作为包内明细。

**模板与快照：**

| 规则 | 说明 |
|------|------|
| 包族编码 | 表示同一业务含义的定数包，如骨科手术包 |
| 模板版本 | 包模板发布后生成版本号，禁止覆盖旧版本 |
| 标签快照 | 打包生成定数标签时固化当时的包内明细、包装数量、批号、效期、价格等快照 |
| 历史追溯 | 历史定数包永远按生成标签时的快照进行消耗、反消耗、红冲和追溯 |
| 版本替换 | 新版本发布后默认自然替换；旧版包继续可用，消耗完后只补当前启用版本 |
| 安全库存 | 默认按包族汇总可用包数，自动补货按当前启用版本生成 |

**定数包定义与成包条件：**

定数包不是多品规组合包，而是同一商品的包装化库存单位。成包商品必须满足同商品编码/商品目录主键、同规格、同型号、同厂家、同供应商、同生产批号、同效期、同批次单价、同所有权、同结算模式、同库房。定数包不要求同系统批次，可在上述条件一致时跨系统批次打包；跨系统批次时必须保存来源系统批次、来源数量、货位、入库单号和批次单价明细。禁止跨库房打包，允许同库房不同货位合并打包。

定数包标签号规则为 `D + 年月日 + 后六位序列号`。打包扣减按同效期下先进先出 FIFO 执行，并记录实际来源系统批次明细。单价不同不允许混包；所有权或结算模式不同不允许混包；买断、寄售、实销实结等不同库存不得混包。

**成包模式与余数处理：**

| 场景 | 规则 |
|------|------|
| 验收入库自动成包 | 验收审核通过后按验收单数据、定数包系数和完整成包条件自动生成定数包库存和标签 |
| 待确认打包任务 | 系统生成待确认任务并默认预占来源散货，人工确认后扣减散货并生成定数包 |
| 模式配置 | 自动成包 / 生成待确认打包任务均支持前台配置 |
| 不能整除 | 按 `floor(可打包数量 / 定数包系数)` 生成整包，余数保留为散货库存 |
| 余数合并 | 余数散货可与后续来货合并打包，但必须满足完整成包条件 |
| 历史散货初始化打包 | 商品启用定数管理后，历史散货需人工发起初始化打包，必须遵守完整成包条件并保存来源系统批次明细，不产生消耗和结算 |

待确认打包任务确认前不计入定数包安全量；预占散货从可用库存中扣除，只计入库存总量，不计入定数包安全量。任务取消、超时释放或重算时释放预占散货。未确认打包任务必须具备超时提醒/释放机制，是否自动释放支持配置。预占散货发生调价、盘亏、召回或隔离时，必须校验或重算相关未确认打包任务。

定数包系数变更需要弹窗提示影响范围，是否审批/复核按风险配置。系数变更只影响后续打包和未确认打包任务；已确认成包不自动变更。预计重算只作用于未确认打包任务，并按最新系数对可用散货重新分组计算包数和余数。提示需展示原系数、新系数、影响任务数、原预计包数、新预计包数、原余数、新余数和预计来源库存变化。

**标签打印与补打：**

| 场景 | 规则 |
|------|------|
| 自动成包打印失败 | 保留定数包库存为待打印/待贴标状态，不回滚库存 |
| 待打印/待贴标 | 计入可用库存和安全量，可被补货任务选中，但出库前必须完成标签打印/贴标 |
| 原标签补打 | 支持勾选原标签打印，不生成新标签号，必须记录打印次数和打印人 |
| 补打原因 | 必选：破损、丢失、字体不清晰、打印模板有变动、无法扫码等 |
| 禁止补打 | 已消耗、已作废、已报损标签默认不允许补打 |
| 召回/隔离补打 | 允许直接补打原标签，但召回/隔离状态不允许消耗 |

补打不增加库存、不改变包状态、不改变来源批次和结算。批号/效期调整后，已打包未消耗定数包默认不强制重打标签，只留痕。

**数量与展示口径：**

| 字段 | 说明 |
|------|------|
| 定数包数量 | 本次发生的包数，如 1 包或红冲 -1 包 |
| 包装数量 | 每个定数包内某个明细的标准数量 |
| 明细数量 | 定数包数量 × 包装数量 |
| 结算金额 | 永远以明细数量、明细单价和明细金额为准 |
| 院内查询 | 同表显示定数包数量、包装数量、明细数量，用字段区分，无需展开 |
| 供应商结算 | 只推送商品明细，不出现定数包汇总行 |

**事件流水：**

定数包账务真相以不可变事件流水为准，当前状态只作为查询快照。已产生事件不得编辑或删除，纠错只能追加补偿事件。

| 事件类型 | 说明 |
|----------|------|
| 打包 | 从散货库存扣减明细，生成定数标签和包内快照 |
| 出库/配送 | 中心库向科室二级库配送 |
| 科室签收 | 科室确认收到定数包 |
| 消耗 | 拆包即整包消耗，生成正向消耗事件和明细结算数据 |
| 反消耗 | 仅用于误操作且实物完整的场景，生成反向事件 |
| 重新消耗 | 若反消耗错误，不删除反消耗记录，只追加新的正向消耗事件 |
| 退回/重打包 | 对不满足原包恢复条件的实物进行退回、拆解、重新打包并生成新标签 |
| 作废/召回 | 标签损坏、质量召回、报损等场景 |

每条事件至少记录 eventId、eventType、sourceEventId、packageLabelId、operatorId、occurredAt、businessPeriod、accountingPeriod、reasonCode、审批记录和外部推送回执。正式统计、报表、大屏和结算均以 accountingPeriod（入账期/结算月）为准；businessPeriod 仅用于追溯、审计和异常分析，不回写历史月份指标。

**反消耗与红冲：**

| 场景 | 处理规则 |
|------|----------|
| 日清前误消耗 | 可发起反消耗，记录原因和操作日志 |
| 日清后误消耗 | 进入科室审批，审批表单必须包含实物完整核验字段 |
| 已结算误消耗 | 允许反消耗；不修改历史结算单，生成次月红冲结算数据 |
| 反消耗后恢复 | 科室审批通过后复活原定数包标签并恢复原科室定数包库存 |
| 反消耗错误 | 不删除反消耗记录，只能追加新的正向消耗和补结算记录 |

科室审批必须核验原定数标签是否存在且可扫码、包装/封签是否完整、包内明细是否未替换、是否仍在原科室库位、是否涉及高值/冷链/无菌/植入类物资，并填写反消耗原因、审批人工号或电子签名。

反消耗后，一正一反记录均保留。原消耗记录不物理删除；系统通过事件链关联原消耗、反消耗、重新消耗、红冲结算明细和供应商推送明细。

已结算定数包反消耗审批通过后，必须在同一业务闭环内恢复库存并生成财务红冲结算数据，不设置“库存已恢复但财务待处理”的正常业务状态。若因系统异常导致红冲数据生成失败，应告警并重试，不作为可长期停留的业务流程节点。召回或隔离包发生反消耗时，复活后的原标签仍保持召回/隔离状态，不直接恢复为可用；召回、隔离、待复核标签均不计入安全量。

**质量召回与补货：**

| 规则 | 说明 |
|------|------|
| 召回命中 | 质量事件命中包内任一明细时，原定数包整包停用 |
| 标签处理 | 停用后如需再形成定数包，必须重新打包并生成新标签，不得复用旧标签 |
| 安全库存 | 召回/停用包不计入科室安全库存 |
| 补货动作 | 召回或停用导致低于安全库存时，自动生成补货任务，人工复核后出库或打包 |
| 任务优先级 | 召回补货与普通请领平级，统一进入任务队列 |
| 队列排序 | 平级任务按综合评分排序，而非纯创建时间排序 |

综合评分由院区配置，集团提供默认模板。评分维度包括期望到达时间、缺口比例、科室等级、风险标签等；权重总和必须为 100%。任务生成时固化公式版本和分数明细。权重修改默认不自动重排已有任务，管理员可手动重算待处理任务；已完成任务和进行中任务不重算。

**解包回散货与作废重组：**

为避免术语混淆，系统区分“拆包消耗”和“解包回散货”。拆包消耗是科室使用场景，拆包即整包消耗并生成消耗及结算事实；解包回散货是库管维护场景，用于未消耗定数包因调价、标签错误、包装破损、系数配置错误、自动成包错误等原因作废回散货，不产生消耗、不产生结算、不计入盘点差异。

| 规则 | 说明 |
|------|------|
| 操作权限 | 是否允许中心库、科室现场或指定角色操作，由菜单/按钮权限配置控制 |
| 位置归属 | 解包后散货位置以当前实物所在库房/货位为准，不自动回原来源货位 |
| 库存影响 | 定数包库存 -1，来源系统批次散货数量 + 包装数量，库存总价值不变 |
| 标签处理 | 原包标签作废；重新组包必须生成新定数包标签，不复用原标签 |
| 散货消耗 | 解包后的散货是否允许直接消耗，按商品、科室、角色和业务策略配置控制 |
| 留痕要求 | 记录原包、来源批次、解包原因、操作人、时间、当前库房/货位和新包关联 |

未消耗定数包内任一来源系统批次调价时，必须保证调整后包内来源批次单价仍一致；否则不允许直接调价生效，系统弹窗提示需先解包回散货/作废重组。自动成包错误支持通过解包成散货/作废重组纠正，不允许直接修改包标签号、商品、包装数量、来源系统批次明细、批号、效期、单价、所有权或结算模式等核心内容。

**配送、拒收与纠错：**

- 定数包出库后签收前处于在途状态；科室签收后才计入科室库存和安全量。
- 科室正常拒收时自动回中心库库存；错送、科室不需要、配送取消可回中心库可用；破损、标签不清、近效期争议、召回/停用、温控异常、数量差异等异常拒收自动回中心库但状态为待复核或隔离，不计可用。
- 错误签收通过纠错调拨或退回重配处理，保留原签收记录，不直接删除。
- 定数包补货任务生成时不锁定具体包，拣配扫描包标签时才锁定；拣配取消或锁定超时释放包库存。

**幂等、并发与 PDA 离线：**

所有会改变定数包状态的接口必须强制携带幂等键。PDA/前端生成 clientRequestId，服务端落库为 idempotencyKey；同一幂等键重复请求返回首次成功结果，不再新增事件。消耗、反消耗、重新消耗、召回停用、补货任务生成等动作均必须满足幂等要求。

同一个 packageLabelId 的状态变更采用版本号或事件序号控制并发。状态变更请求必须携带 expectedVersion；服务端校验当前版本一致后才允许追加事件并更新快照。版本冲突请求不得直接落账，应返回当前最新状态，由操作端重新处理。

PDA 离线时只允许扫码/记录类采集并保存在本机待上传队列，不改变服务端正式库存和结算数据。允许离线暂存的业务包括盘点扫码、定数包消耗扫码、科室收货扫码、上架/拣货扫码、温度人工记录、异常照片和备注。离线期间禁止审批、反消耗、召回/停用、结算/对账/红冲、主数据维护、定数包模板修改、跨库调拨确认、供应商推送等强一致操作。

PDA 端必须持续提醒当前设备已离线，并将离线采集数据显示为"本机待上传"状态；同一设备内应防止重复扫码。上传成功前不得显示为正式入账，不得影响 PC 端库存、科室库存、安全库存和结算数据。恢复网络后自动上传；上传成功后状态变为已入账，上传失败按现有业务错误提示处理，不建设独立离线异常处理台。

PC 端根据 PDA 离线时间进行提醒和业务数据展示。提醒内容至少包括设备编号、所属科室/库房、离线时长、最后在线时间、最后操作人等。后补上传数据按服务端处理时间确定 accountingPeriod，并打"离线补传"标识；离线发生时间仅用于查询和审计，不回写历史月份指标。

## 8.5.8 耗材出入库查询

整合所有出入库流水（含期初、采购入、调拨入、退货入、申领出、消耗出、调拨出、退供应商出、盘亏盘盈等）：

| 查询字段 | 说明 |
|----------|------|
| 业务类型 | 多选 |
| 单据号 | 模糊搜索 |
| 商品 / 批号 / 效期 | - |
| 库房 / 货位 | - |
| 时间范围 | 必填 |
| 经办人 | - |
| 出入库金额 | 区间 |

支持导出 Excel、生成审计专用流水。
