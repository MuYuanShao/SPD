# 5.2 库存管理

> 所属模块：5. 供应链业务模块
> 来源：院内SPD系统产品需求文档.md

## 当前产品边界（2026-07-13）

- 本功能是仓库、商品、批次和货位维度的**库存余额查询**，不得混入库存交易历史。
- 库存交易历史是独立功能；“库存事件快照”不是业务模块，不在本页或其他业务页面展示。
- 所有收货、FIFO 扣减、调整、调拨和隔离必须通过库存移动服务完成，保证余额非负并写不可变库存事件。
- 数据库以标准化货位身份保证无货位余额唯一；FIFO 扣减锁定候选余额并使用非负更新条件。

## 5.2.1 功能概述

库存管理是SPD系统的核心模块，涉及医院医疗物资的入库、出库、盘点、调拨等全生命周期管理。

```
├── 库存总览
├── 入库管理
│   ├── 采购入库

│   ├── 科室领用出库

```

## 5.2.3 入库业务规则

| 规则 | 说明 |
|------|------|
| 批次管理 | 同一商品不同批次分开管理 |
| 效期管理 | 先进先出（FIFO）原则 |
| 验收要求 | 到货必须验收，不合格不得入库 |
| 扫码要求 | 高值耗材必须扫码入库 |
| 冷链要求 | 冷链商品必须记录温度数据 |

## 5.2.4 出库业务规则

| 规则 | 说明 |
|------|------|
| 先进先出 | 优先出库较早入库批次 |
| 效期预警 | 优先出库近效期商品 |
| 扫码出库 | 高值耗材必须扫码出库 |
| 审批控制 | 特殊商品出库需审批 |
| 库存校验 | 出库前校验库存是否充足 |

## 5.2.7 库存状态机与事件快照

库存余额不得由人工直接改最终数值，所有变化必须来自业务单据、定数包事件、盘点调整或系统调整事件。库存查询可使用实时快照表提升性能，但账务真相以库存流水和定数包事件流水为准。

| 状态 | 含义 | 进入来源 | 退出来源 |
|------|------|----------|----------|
| 可用 | 可被申领、拣配、配送或打包 | 合格入库、复核通过、盘盈调整 | 锁定、出库、召回、盘亏 |
| 锁定 | 已被申领、手术单、采购退货或调拨占用 | 申领提交、手术备货、退货申请 | 出库、取消、超时释放 |
| 在途 | 已出库但未被目标库房签收 | 配送出库、跨库调拨出库 | 目标签收、运输异常处理 |
| 隔离 | 不可用，待质控或库管判定 | 冷链超温、召回命中、退回待判定、不良事件 | 转可用、报损、退供应商、销毁 |
| 待复核 | 实物与系统状态需要人工核验 | 反消耗、盘点差异、离线补传冲突 | 审批通过、驳回、系统调整 |
| 待上传 | PDA 本机暂存，未入服务端账 | PDA 离线扫码/记录 | 上传成功、上传失败后重新处理 |

**事件与快照一致性规则：**

- 库存快照只用于查询和看板；事件流水、出入库流水、定数包事件流水是账务依据。
- 系统提供快照重建任务，可按商品、批号、库房、定数包标签重新计算余额。
- 快照与事件重放结果不一致时，生成库存一致性告警，禁止直接手工改余额。
- 纠错必须追加调整事件、盘盈盘亏事件、反消耗事件或重新消耗事件。
- 盘点差异关闭时必须生成盘盈/盘亏调整事件，并关联原盘点单和审批人。
- 全系统以进销存一致为底线，任何出库、配送、消耗、打包、调拨、退供应商、报损、召回处理和 PDA 补传均不得形成负库存。库存不足时只能进入缺货、待补货、待调拨、待采购、应急借用或待复核状态。

## 5.2.8 系统批次、批号效期与批次单价

系统批次是库存、调价、退货、消耗、盘亏、报损和追溯的账务对象；供应商/生产批号与效期是批次属性，不等同于系统批次号。

**系统批次生成规则：**

| 规则 | 说明 |
|------|------|
| 生成时点 | 验收单审核通过后生成系统批次；人工保存未提交或待审核验收单不生成批次 |
| 批次号规则 | 审核通过日期 `YYYYMMDD` + 后五位自然序列号 |
| 归并判断 | 同一验收单号 + 同一耗材商品目录主键 + 同一生产批号 + 同一效期，归入同一系统批次 |
| 拆分判断 | 验收单号、商品目录主键、生产批号、效期任一不同，拆分生成不同系统批次 |
| 跨天录入 | 同一验收单跨天或多次扫码录入时，以审核通过时的验收单数据为准，不按录入日期拆批 |
| 部分验收 | 同一采购来源分次形成不同验收单或不同审核日期时，按实际审核通过的验收单生成批次 |

**所有权与结算模式快照：**

- 库存流水、库存快照、系统批次、定数包标签快照均必须固化所有权类型和结算模式。
- 所有权类型包括医院买断、供应商寄售、代管等；结算模式包括采购入库结算、科室消耗结算、实销实结、赔付结算等。
- 同一商品同一供应商也可能存在不同合同批次、所有权或结算模式，不得只依赖商品主数据判断。
- 盘亏、报损、退供应商、定数包消耗、红冲和供应商对账必须读取库存对象快照中的所有权和结算模式。
- 买断库存和寄售/实销实结库存禁止混入同一个定数包。

**批号/效期调整规则：**

- 系统批次号不可变更。
- 生产批号、效期可按批号批量调整，调整必须审批并留痕。
- 批号/效期调整为追溯属性更正，允许全量影响当前库存、已打包、已消耗、已结算等记录的展示和追溯属性。
- 批号/效期调整不改变数量、金额、单价和结算状态，不生成供应商追溯信息更正通知，不触发对账/发票重推。
- 调整记录必须保存调整前值、调整后值、调整单号、调整人、审批人、调整时间和影响范围。
- 召回查询必须支持按调整前和调整后的批号/效期都能命中；召回结果以当前更正后的批号/效期展示。
- 批号/效期可调整为与其他系统批次相同，但系统批次不合并。

**批次单价与调价规则：**

- 验收入库审核通过时，系统读取最新商品目录采购单价生成批次单价；采购订单价格仅作为计划价、预估价和数据分析依据。
- 若验收入库时商品目录最新采购单价与采购订单单价或验收预览价不同，系统弹窗提醒并留痕，不阻断验收。
- 批次单价一经验收固化，后续结算以批次单价为准；合同价、集采价只作为商品目录采购单价维护的参考。
- 商品目录采购单价变更只影响后续新验收入库批次，不自动改变历史批次。
- 商品目录采购单价维护错误导致已验收批次价格错误时，只能走调价管理按批次调价，或退货后重新采购/重新验收。
- 批次单价调整必须审批通过后生效并生成价格版本，记录原单价、新单价、原因、依据附件、审批人和影响清单。
- 批次单价调整不覆盖已消耗、已结算、已计费的数据。普通耗材一旦产生消耗数据即固化原消耗单价；验收入库即结算商品在验收结算后固化原入库单价；高值耗材绑定患者并计费后固化原计费单价。
- 未产生结算事实的数据随批次单价调整变化，包括中心库库存、锁定未出库库存、在途未签收库存、科室已签收未消耗库存、已打包未消耗定数包、未绑定患者/未计费高值耗材、冷链隔离或召回但未消耗库存。
- 已产生消耗、验收入库结算或患者计费事实的数据如需纠错，走补差、红冲、计费冲销或财务调整，不直接改原单价。
- 反消耗负向记录必须按原正向消耗记录的单价和金额反向冲回。
- 未消耗库存盘亏、报损、赔付和科室成本按盘亏/报损时有效批次单价计算。
- 科室未消耗库存价值随批次单价调整变化；已消耗成本保持原消耗单价。

**退货重新采购规则：**

- 退货重新采购必须保留原验收入库单、原系统批次、原批次单价和原业务记录。
- 原批次已发生的消耗、结算、患者绑定、反消耗、红冲记录继续挂在原批次，不迁移、不合并到新批次。
- 可退库存通过采购退货单扣减原批次；重新采购生成新采购流程、新验收单、新系统批次和新批次单价。
- 原批次与新批次通过退货重采关系关联，支持追溯但不合并账务事实。

## 5.2.9 盘点、盘盈盘亏与责任成本

盘盈和盘亏均必须基于真实库存对象处理，不允许通过负库存或无来源库存表达差异。

| 场景 | 处理规则 |
|------|----------|
| 盘盈 | 盘点录入时不直接增加可用库存；复核确认来源后，可生成盘盈入库调整事件并增加可用库存 |
| 盘亏 | 盘亏前提是系统有库存但现场实物不存在或少于系统库存，只能针对系统当前存在的库存对象发起，不存在负库存 |
| 定数包盘点 | 以包标签为主盘点；系统无可用标签的实物包不能直接盘盈为定数包，应复核或重新打包 |
| 高值/冷链盘点 | 必须按 UID/唯一码处理，异常进入追溯、质控或安全审计 |
| 预占散货盘亏 | 扣减预占库存并触发相关未确认打包任务重算 |

盘亏复核通过后扣减系统库存，生成盘亏事件，记录责任科室、保管人、发现人、复核人、审批人、原因、库存对象、有效批次单价和损失金额。盘亏必须计入科室成本/绩效责任。盘亏是否生成供应商结算或赔付数据，按库存所有权和结算模式判断：买断库存通常只影响院内成本；寄售/实销实结库存应按配置生成供应商结算、赔付或对账处理。
