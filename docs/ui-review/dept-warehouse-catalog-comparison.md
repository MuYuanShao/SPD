## 一、页面总览（已完成形态）

科室库房管理页由三段构成，自上而下：

1. **查询条** —— 科室 / 库房 / 商品关键字 / 维护来源 / 状态，下方为「查询」「重置」。
2. **工具栏** —— 「新增」「批量导入」「导出 Excel」「列设置」等操作按钮。
3. **数据表格** —— 10 列：选择框、科室/库房、商品编码、商品名称、规格型号、生产厂家、维护来源、状态、更新时间、操作。

表格特性：

- 表头**水平居中**，与数据行的列分隔线**像素级对齐**（实测 `delta = 0`，见第五节）。
- 移除自定义拖拽手柄，改用 **Element Plus 原生表头边框拖拽**调列宽，宽度持久化到 `localStorage`。
- 「商品名称」「生产厂家」两列支持**自动换行**，并保留 `title` / Tooltip 兜底查看全文。

## 四、组件规格总览（按钮 + 状态条）

### 4.1 统一规格

**按钮与状态条共用同一套视觉规格**：

```
圆角 4px · 边框 1px solid <语义边框色> · 背景 语义色 0.4 透明度 · 文字 语义深色
```

CSS 实现（`frontend/src/styles/list/unified-list.css`）：

```css
border-radius: var(--spd-c-chip-radius, 4px);
border: var(--spd-c-chip-border-width, 1px) solid var(--spd-c-success-border);
background: var(--spd-c-chip-bg-success);   /* color-mix(in srgb, <语义色> 40%, #ffffff) */
color: var(--spd-c-success);
```

实测 computed style（三方案一致）：

```
borderRadius = 4px      borderWidth = 1px
background   = color(srgb 0.648 0.766 0.762)   /* 即 0.4 透明度底 */
color        = rgb(20, 85, 82)                  /* 深色，非白字 */
```

## 六、三档字号系统

| 档位 | 基准字号 | 行高（标准行） | 适用人群 |
| --- | --- | --- | --- |
| 标准 standard | 14px | 90 – 126px | 常规显示器，密度优先 |
| 大 large | 16px | 98 – 154px | 27 寸以上屏幕、轻度老花 |
| 特大 xlarge | 18px | 107 – 164px | 视力偏弱、高分辨率远距 |

实现方式：`<html data-font-size="standard|large|xlarge">` 驱动，
所有 `--spd-font-size-*` 由 `--spd-fs-base` 推导，整站等比缩放。
用户选择持久化到 `localStorage`（键 `spd.theme.fontSize`），顶栏「主题面板 → 界面字号」可随时切换。

采集脚本实测三档均生效：

```
standard → html font-size 14px
large    → html font-size 16px
xlarge   → html font-size 18px
```

四档分辨率均**无横向滚动条**，表格始终铺满内容区。

| 方案 | 1920px | 1600px | 1366px | 1280px |
| --- | --- | --- | --- | --- |
| A 固定宽 | 表宽 1884 / 无滚动 | 1564 / 无滚动 | 1330 / 无滚动 | 1244 / 无滚动 |
| B 自适应 | 1884 / 无滚动 | 1564 / 无滚动 | 1330 / 无滚动 | 1244 / 无滚动 |
| C 混合 | 1884 / 无滚动 | 1564 / 无滚动 | 1330 / 无滚动 | 1244 / 无滚动 |

> 表格宽度始终等于内容区宽度，说明三方案在当前实现下都已适配容器；
> 差别在于**列宽如何分配**以及**窄屏下行高如何变化**。

### 各方案行高对比（标准字号 14px）

| 方案 | 1920px | 1600px | 1366px | 1280px |
| --- | --- | --- | --- | --- |
| A | 90 / 113 | 90 / 113 | 90 / 113 | 90 / 113 |
| B | 90 / 113 | 90–136 | **126–136** | **126–136** |
| C | 90 | 90–136 | 90 / 158 | 90 / 158 |

**关键差异**：窄屏（1366 / 1280）下，方案 B 的**所有行**都被拉到 126px 以上，
信息密度明显下降；方案 A 行高完全不受视口影响；方案 C 短字段行保持 90px，
只有长文本行被拉伸。

| 列 | A 固定宽 | B 自适应 | C 混合 |

| 商品编码 | 155 | 134 | 130 |
| 商品名称 | 300 | 268 | 286 |

| 生产厂家 | 290 | 257 | 285 |
| 维护来源 | 130 | 112 | 105 |

## 十、推荐方案

### 推荐：**方案 C（混合列宽 + 典雅松竹绿）**

**理由：**

1. **扫读稳定性最强** —— 短字段列（编码 / 状态 / 来源 / 时间）在任何视口下列位不变，
   30+ 用户持续扫读时视线不会因窗口缩放而重新定位。这是本次改造的首要目标。
2. **窄屏密度不塌陷** —— 1366 / 1280px 下短字段行仍为 90px，一屏可见记录数不缩水；
   方案 B 会让整表涨到 126px 以上。
3. **长文本优先保障** —— 「商品名称」「生产厂家」两列优先吸收剩余空间，
   在 65 字符极限数据下换行行数最少（实测 4–5 行），信息完整不截断。
4. **配色最耐看** —— 松竹绿 `#245b45` 明度低于青玉，浅底深字对比柔和，
   长时间连续值班的疲劳感最低。

### 若更看重「列宽完全可控」，选方案 A

用户拖拽后列宽**绝对锁定**，不会因视口变化而重排。代价是窄屏下长文本列被压得更窄，
换行行数偏多（58–65 字符商品名需 5 行以上）。

### 不推荐方案 B 作为最终态

主要问题在窄屏：所有行行高被拉到 126–136px，**一屏可见记录数下降约 30%**，
且列位随视口漂移，与「面向 30+ 用户的稳定扫读」目标相悖。

### 落地方式

当前三个方案分支并列存在，选择后把对应分支的
`frontend/src/styles/tokens/palette-X.css` 与 `frontend/src/styles/layout/column-strategy-X.css`
合并进 `feature/ui-readability-base` 即可，无需重写业务代码。
