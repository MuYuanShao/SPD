# 院内 SPD 系统架构

## 分层

- `backend`：Spring Boot 后端服务，负责认证、主数据、供应链、追溯、配置和扩展业务 API。
- `frontend`：Vue3 管理端，负责菜单、路由、模块工作台和接口联调。

## 后端模块

- `system`：启动、健康检查、系统模块目录。
- `foundation`：登录认证、用户、角色权限、科室。
- `masterdata`：商品目录、供应商、厂家、审批目录。
- `supplychain`：采购、库存、科室申领、结算对账。
- `specialty`：UDI、高值耗材、冷链。
- `operations`：报表、系统配置、SaaS 配置中心。
- `extension`：院内 SPD 业务扩展与合规扩展。
- `common`：统一响应、错误码、跨域、安全等通用能力。

## 组织与库存模型

组织层级按 PRD 采用：

```text
集团/租户 -> 医院 -> 院区 -> 科室 -> 库房/货位
```

其中科室是用户归属、数据权限、申领、消耗、日清和责任成本维度；库房是库存账务空间，科室二级库需关联科室。

## 分类口径

商品目录中的“商品分类”仅作为商品主数据字段管理，用于商品目录维护、列表查询、导入导出和基础检索。该分类不直接参与补货、定数包、日清、调价、反消耗等业务策略配置。

配置中心中的分类类条件需作为独立的“策略分类”或“规则分组”建模，不复用商品目录分类字段。两者可以通过显式映射关系做统计或规则适配，但不能默认等同。
