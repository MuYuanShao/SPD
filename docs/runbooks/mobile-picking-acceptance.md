# 移动三类拣选接入

本阶段在已有签收接口上增加按申领明细执行的散货、实际定数包和高值唯一码拣选，支持分次完成并返回配送单与剩余申请量。账号权限仍由管理员配置，不自动授权。

## 1.3.3 按申领单进入、单内连续扫码

入口调用GET `/api/mobile/picking/orders`，按申领单在服务器分组分页，待处理数按单据计数。搜索商品只筛选相关单据，不会截断该单明细。点击单号后，GET `/orders/{id}`一次读取该单全部有效待拣明细，不受原明细列表20条分页限制；单据完成后仍可回读完成状态。

单内POST `/orders/{id}/scans/resolve`只在当前申领单的授权范围内识别商品/包码/唯一码。单一匹配自动进入对应明细并核验该码；多条匹配显示选择，不默认第一条；其他单据的码拒绝。每项仍沿用原预校验、人工确认和幂等库存事务，完成后刷新原单并将焦点交回单内扫码框，不跳回全局列表。结果未知时保留原记录，查询/恢复后仍回到所属申领单。

新增权限沿用department-requisition:pick；没有新增角色授权或数据库迁移。验证：40项独立MySQL验收通过，含25条明细完整加载、同码25条候选不静默选项、跨单拒绝、本人范围隔离及完成单据回读；后端全量830项，失败0、错误0、环境跳过114。浏览器验证散货、包、高值连续处理、PDA焦点、重启恢复和同码手动选择。

## 接口与权限

新增 `/api/mobile/picking/tasks`、`/tasks/{itemId}`、`/scans/resolve`、`/operations/validate`、`/operations/recover`、`/operations`。查询参数包含 deptId 与 warehouseId，表示原申领目标科室与库房；来源库来自原单。

这些接口统一要求 `department-requisition:pick`，并检查科室、目标库房、明细状态和原来源库。本人范围只列出本人申请，详情、扫码和提交也不能绕过。`picking-delivery:write` 不替代拣选权限。

`GET /api/mobile/operations/{operationId}` 继续按操作归属查询，拣选回执要求拣选权限、签收回执要求签收权限，且仅返回本人操作结果。`/api/mobile/context` 根据已有权限返回 PICK_LOOSE、PICK_PACKAGE、PICK_HIGH_VALUE 及 SIGN_DELIVERY。

## 提交约束

- 一次只处理一个申领明细，保留原来源及目标，不跨单据合并。
- 散货：rawCode 为商品编码或商品主数据 UDI；quantity 按基本单位传递，必须为正整数，最多14位。前端、移动预校验和实际业务提交均遵循当前SPD的 QuantityRules，不允许小数。
- 定数包：packageIds 为实际标签 ID，quantity/rawCode 留空，数量由后端按包内基本单位数量求和，并核对模板版本和来源批次。
- 高值：traceCodeIds 为稳定追溯 ID，quantity/rawCode 留空，每个实物计 1，不能用包码代替。
- 预校验返回五分钟有效摘要；人工确认后才提交。最终事务重新读取当前申请量和实物状态，不能依据旧库存直接执行。
- 同用户同 operationId 同载荷返回原回执；不同载荷返回 409。首次提交失败时回执与业务同回滚；恢复接口可以保留pending回执并签发新摘要，不改原编号和业务内容。终止回执会阻止迟到请求再次执行。
- 拣选事务采用 READ_COMMITTED，并锁原申领，避免等待并发锁后仍使用旧剩余数量。

## 已确认库存时点

1. 散货拣选扣来源散货并保存配送原批次；签收按原批次入目标库，不二次扣来源。
2. 定数包在制包确认阶段已扣散货，拣选只绑定实际包、更新包状态并生成配送单，不能再次扣散货。签收按包来源批次入目标库。
3. 高值拣选绑定唯一码及配送，签收才按确切唯一码批次转库；不触发手机收费消耗。

## 验收

使用 `scripts/test-mobile-isolated.ps1` 的随机数据库和独立 MySQL 实例，真实 HTTP 测试覆盖：

- 散货 4 个申请分两次各拣 2，回执返回剩余 2、0；重复提交不再扣库。
- 一个 2 个/包的实际标签按 2 个计算；制包前置已扣，拣选不再扣散货。
- 高值选 2 个唯一码，拣选库存不变，签收后来源减少 2、目标增加 2，零消耗计费写入。
- 同明细两个不同操作号并发各拣 3，4 个申请只允许一次成功，不超拣。
- 错来源、错物料、重复包码、过时摘要拒绝；拣选权限取消后不能读取原拣选回执。
- 本人范围不能列出或读取同科室其他申请人的明细。

原有签收及权限修复验收保留，当前独立 MySQL 共 13 项通过。
