# MCP-UI 第一期采购对接

接收地址为 `/api/mcp/receive`。本模块只接收 **待审批目录及审批附件**，不直接修改院内目录；复用现有目录新增、变更及审批附件业务服务。处理回执的 `processed` 表示已进入待审批目录，审批仍由院内人员完成。

## 数据库与启用

部署新版后端执行 Flyway V88/V89。V88新增对接映射、幂等结果、来源证照及上传状态表；将供应商、厂家、订单更新时间提升到微秒精度，并在采购明细新增、修改、删除时更新订单版本。V89为上传状态补充目标身份，切换服务器地址后可重新同步数据。数据库迁移账户需要创建触发器权限。

### 页面配置IP地址

打开 **系统配置 → 系统集成 → MCP-UI对接地址**，填写连接协议、MCP-UI服务器IP地址或域名、端口，点击“保存对接地址”。页面自动生成 `/api` 根地址，不需要填写接口路径或编辑环境变量中的连接地址。例如 IP `192.168.1.20`、端口 `8080`、HTTP 对应 `http://192.168.1.20:8080/api`。

地址保存于现有 system_config，配置键 `integration.mcp-ui.connection`，范围为 global/default。下一次上传任务自动读取新地址，无需重启；地址变化时清除旧登录令牌及cookie，再登录目标服务器。页面设置优先于旧环境变量；停用或过期的页面配置会阻止上传，不回退至旧地址。账户及密钥仍按下表配置。

模块默认关闭，未配置时不会接收商品或发起上传。服务器运行环境变量：

| 变量 | 内容 |
|---|---|
| `SPD_MCP_ENABLED` | `true` 启用对接；默认 false |
| `SPD_MCP_ORGANIZATION` | 与 MCP-UI 实例机构标识完全相同 |
| `SPD_MCP_SHARED_TOKEN` | 强随机共享密钥，与 MCP-UI 实例环境变量的值一致 |
| `SPD_MCP_OPERATOR_ID` | SPD-PR 内有效服务账户ID，用于待审批申请与审计；必须拥有对应申请修改和附件访问权限 |
| `SPD_MCP_UPLOAD_ENABLED` | `true` 开启资料和采购订单上传；默认 false |
| `SPD_MCP_UI_URL` | 兼容旧部署的API根地址；未保存页面地址时才使用，已在系统配置填写IP地址后无需设置 |
| `SPD_MCP_UI_INSTANCE_ID` | MCP-UI 创建的实例UUID |
| `SPD_MCP_UI_TENANT_ID` | MCP-UI 账户租户ID，默认 1 |
| `SPD_MCP_UI_USERNAME`、`SPD_MCP_UI_PASSWORD` | MCP-UI 专用上传账户，授予 `integration:upload` |
| `SPD_MCP_UI_API_KEY` | MCP-UI 平台接口密钥；直连及登录请求使用 |
| `SPD_MCP_CURRENCY` | 明确配置真实三位币种，例如 CNY |
| `SPD_MCP_TAX_INCLUDED` | 明确配置来源金额口径：true 含税、false 未税 |
| `SPD_MCP_SOURCE_ZONE` | 数据库时间所属时区，默认 Asia/Shanghai |

上传间隔由 Spring 属性 `spd.mcp.upload-delay-ms` 配置，默认60秒。每次分页读取厂家、供应商及完整采购订单，首次自动初始化存量，后续按数据摘要跳过已成功记录；失败记录下次继续上传。任务使用 MCP-UI 登录、refresh cookie 和短期访问令牌，不把令牌写入配置或日志。网络失败不更新已成功水位；单条业务失败记录在 `mcp_upload_state`。

订单保留真实来源状态：draft、pending_approval、approved、sent、closed、rejected、voided；MCP-UI 报表排除草稿、驳回、作废和取消。sent 是“订单已发送供应商”，不是已发货。遇到未定义状态停止该订单并记录失败，不猜测。采购日期取订单 create_time 的日期，明细金额来自实际 amount，单价来自 estimated_unit_price。此来源系统的字段名保留在适配器中，不能据此把它解释成结算或实际入库价格。来源系统未逐单记录币种与税口径，第一期使用明确配置的系统统一口径；混合口径订单不能启用此上传模式。

## 商品与证照接收规则

- 接收器只信任本院共享密钥和本院机构标识；从数据库加载配置的有效服务账户及权限，保留既有审批访问规则。
- 幂等键必须与 syncId 相同；同一 syncId 不允许不同内容。来源商品ID、SPD商品编码与申请编号持久关联。
- 商品新增进入新品准入申请；仍待审批的申请按现有服务更新；院内已有商品的新版本进入变更或停用申请。正在审批的新品不能直接转为院内停用申请，返回明确失败结果，由院内处理现有申请后重新下发。
- 证照只接收真实附件字节，单个最多10MB、合计最多18MB，每个商品最多10份。现有审批附件服务验证文件签名，支持PDF、PNG、JPEG、WEBP。
- 附件使用正常审批附件存储，可在原待审批目录页面查看；证照编号、类型、有效期和状态保存在 mcp_pending_license，并关联 sys_attachment。更新及作废只影响对应来源附件，人工附件保留。
- 原申请已经处理后，仅证照下发创建资质更新申请。到期、作废与新品准入资格仍受院内现有规则约束。
- 商品和证照来源版本分别管理；网络重试使用原请求和幂等键，重新下发才创建新来源版本。

首次联调顺序：执行双方迁移并配置账户和密钥 → 上传厂家供应商 → MCP-UI 选择真实商品及证照下发 → 在 SPD-PR 待审批目录检查申请及附件 → 按正常审批准入 → 创建或选择真实采购订单 → 启用上传并核对 MCP-UI 查询和订购报表。

构建和单元测试不能代替真实MySQL迁移、账户权限及双端联调验收。开发未自动执行现有业务数据库迁移、启动上传或更改审批状态。

目录审查修复需执行V91迁移。证照替换/撤销保存为待审批退休动作，审批后才停用原来源对应的院内附件，人工附件不受影响。独立证照重发同时更新申请的注册证有效期；资质审批不会改变院内原启停状态。下发启停状态与未结束申请冲突时返回失败，要求先处理原申请再重发，不会把最新启用请求继续按旧停用申请执行。

证照审查修复需进一步执行SPD-PR V92及MCP-UI V26。来源证照以不可变 `sourceLicenseId` 识别，编号修改不创建另一张证照。V92独立保存待审批意图和已批准版本：驳回保留原已批准附件，后续批准按已批准版本退役旧附件，并拒绝旧来源版本覆盖。已批准来源证照的状态、有效期及生效日期参与采购提交、审批和发送校验，包括非注册证；草稿允许保存。新品准入校验本次申请的来源证照。

MCP-UI发送 `licensesComplete:true` 完整关联集合，商品关联变化会为原商品自动追加仅证照清理下发，两个商品分别审批。移除关联标记 `unlinked`，不会继续影响原商品采购资格；作废仍关联商品并阻止采购。人工附件不参与来源清理。历史无稳定ID的证照按 `legacy:证照编号` 兼容，首次按原编号承接稳定ID；升级后先全量重发，再修改历史证照编号或关联。

## 第二期收货、入库和库存同步

部署第二期后执行V90迁移。在本页系统集成的MCP-UI对接地址表单中勾选“启用第二期收货、入库和批次库存同步”并保存；默认关闭，不影响一期上传。旧部署也可使用SPD_MCP_PHASE2_UPLOAD_ENABLED=true，但页面保存的phase2Enabled字段优先。

第二期先上传采购收货与验收，再上传采购入库事件及完整当前库存。库存范围为双方已有商品映射的院内商品，金额按当前院内目录采购价估值；散货无货位余额与在库定数包来源批次相加，已签收包不重复计算。每次快照完整替换MCP-UI旧余额，空快照清空旧余额。缺少定数包批次分摊时拒绝生成快照，保留上次有效余额。

采购转收货保留purchaseOrderItemId，新建/编辑请求兼容旧字段，但历史未关联记录只允许唯一匹配。重复商品无法唯一归属时在mcp_upload_state记录失败，不猜测。明确关联的验收数量只更新对应采购明细，入库前检查该明细剩余数量。临时收货不纳入采购履约对接。

入库金额使用不可变事件amount_snapshot并保留snapshot_origin。captured是事件原始金额，legacy_backfill是历史回填值，MCP-UI单独标记和汇总。缺失金额或验收批次关联时记录失败，不用当前价格补造历史金额。

按用户确认，第二期只新增MCP-UI退货接收接口和报表，暂不新增本系统采购退货业务或上传虚构退货。详细字段、样例、报表口径及验收见MCP-UI仓库imports/spd-pr-phase2-contract.md。
