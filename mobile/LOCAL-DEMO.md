# 电脑本地 APP 演示

双击 `D:\SpdApp\启动APP本地演示.cmd`，或启动 Vite 后访问 http://127.0.0.1:1831/?demo=1 。启动脚本仅监听本机，不需要 SPD 后端或 MySQL。

登录账号 `demo`，密码 `demo123`。此账号只在浏览器模拟服务内使用，不能登录真实 SPD。

1. 登录后从三个卡片入口选择“拣选”“签收”或“扫码消耗”，进入业务页后选择“演示科室 · 演示科室库”。
2. 配送签收：打开“演示-配送-10”，确认散货实收、预校验、确认；包签收任务使用 `PK11`、`PK12`。
3. 物料拣选：先选择申领单号，进入本单全部待拣明细。单内扫描散货 `P0`、定数包 `PK701` 或高值 `U901`，按 Enter 自动定位本单明细。校验并确认后点击“完成并继续本单拣选”，留在原单扫描下一商品。
4. 整包消耗：输入 `PK8`，核对1包2个、整包确认、预校验、确认，显示模拟金额20元。也可以先签收演示包，再在消耗入口输入它的包码。
5. 展开手机画面外的“本地演示说明 · 示例码”，点击“重置演示数据”恢复初始场景。关闭浏览器会话后演示数据不保留。
6. 业务页“返回本单明细”会结束可放弃的未提交明细；结果未知时仍禁止丢弃，返回首页后可从“待处理”恢复原记录。单内完成后不会自动跳回全局单据列表。

所有 Axios 请求，包括错误地址和未知API，都在浏览器内处理或拒绝，不会转发给真实服务器。演示状态仅存 sessionStorage；不代表后端数据库验收、Android Keystore、CameraX 或真机网络能力。

## 同一申领单多个商品

打开 `http://127.0.0.1:1831/?demo=1&scenario=multi`，登录demo/demo123后进入“拣选”，入口只展示两个单号。SL-DEMO-20261023-001有5条待拣明细，SL-DEMO-20261023-002有1条。点击第一张单后会展示其全部5条明细；即使入口搜索“注射器”，进入该单后仍展示全部待拣项。

在第一张单顶部直接扫描SYR-5，自动定位5ml注射器明细104；填写整数2、校验并确认后，104待拣8支，105仍待拣10支。点击“完成并继续本单拣选”，直接继续扫描SYR-10或本单其他商品，不必再查找单号。扫描另一张单的INF-1会被拒绝。同码匹配本单多条明细时必须手动选择，不会默认第一条。演示与真实SPD分离。

演示入口仅在 Vite DEV 构建且URL带 `demo=1` 时加载；生产构建不包含模拟服务模块。正式 APK 仍使用真实API与原生加密日志。
